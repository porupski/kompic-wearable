### Transaction formats [p. 22 Figs. 7-9, 7-10]

**Write 16-bit register:**
```
S · 0x90 (W) · A · 0x0X (pointer) · A · data_MSB · A · data_LSB · A · P
```

**Read 16-bit register (after pointer is set or to re-read same pointer):**
```
S · 0x91 (R) · A · data_MSB · A · data_LSB · NA · P
```

**Read 16-bit register (with pointer change):**
```
S · 0x90 (W) · A · 0x0X (pointer) · A · RS · 0x91 (R) · A · data_MSB · A · data_LSB · NA · P
```

**MSB-first** on the wire [p. 20 §7.5.3.1] — **opposite of VEML6030 [20.06]** which is LSB-first. Be careful when reusing I²C driver code across sensors.

### Pointer register persistence

After a write to a pointer, subsequent reads keep returning that register until a new write changes it [p. 21 §7.5.3.1.3]. Saves bytes on repeated reads of the same register (typical pattern: write pointer=0x00 once at init, then `i2c_read(2)` repeatedly).

### Configuration Register (0x01) bit fields [p. 27 Table 7-6]

```
[15]    HIGH_Alert   R    1 = high-limit exceeded (cleared on config read in alert mode)
[14]    LOW_Alert    R    1 = low-limit crossed (cleared on config read; always 0 in therm mode)
[13]    Data_Ready   R    1 = new conversion available; cleared on temp/config register read
[12]    EEPROM_Busy  R    1 = EEPROM programming in progress or power-up
[11:10] MOD[1:0]     R/W  Conversion mode:
                             00 = Continuous Conversion (default)
                             01 = Shutdown
                             10 = Continuous (alias of 00; reads back as 00)
                             11 = One-Shot
[9:7]   CONV[2:0]    R/W  Conversion cycle time (see table below)  default 100 = 1 s
[6:5]   AVG[1:0]     R/W  Averaging:
                             00 = No averaging       (15.5 ms active per cycle)
                             01 = 8 samples (default, 124 ms active)
                             10 = 32 samples         (~500 ms active)
                             11 = 64 samples         (~1 s active)
[4]     T/nA         R/W  0 = Alert mode (HIGH+LOW window detector)
                          1 = Therm mode (HIGH only, with hysteresis from LOW limit)
[3]     POL          R/W  ALERT polarity: 0 = active LOW (default), 1 = active HIGH
[2]     DR/Alert     R/W  ALERT pin source: 0 = alert flag (default), 1 = data-ready flag
[1]     Soft_Reset   R/W  Write 1 → 2 ms SW reset (auto-clears, always reads 0)
[0]     —            R    not used
```

**Factory default 0x0220 = `0000 0010 0010 0000`** [p. 27 §7.6.3]:
- MOD = 00 (Continuous conversion)
- CONV = 100 = 1 s cycle
- AVG = 01 = 8 averages
- T/nA = 0 (Alert mode)
- POL = 0 (Active low)
- DR/Alert = 0 (ALERT shows alert flag, not data-ready)
- → Out of the box, TMP117 samples at 1 Hz with 8× averaging and a usable ALERT mode. **Most apps don't need to touch this.**

### Conversion cycle time vs averaging [p. 28 Table 7-7]

| CONV[2:0] | AVG=00 (no avg) | AVG=01 (8) | AVG=10 (32) | AVG=11 (64) |
|---|---|---|---|---|
| `000` | **15.5 ms** | 125 ms | 500 ms | 1 s |
| `001` | 125 ms | 125 ms | 500 ms | 1 s |

## Initialization sequence

[Synthesized from p. 12 §7.3; p. 27 Configuration register]

```
1. (Hardware) +3.2 V comes up, V+ ≥ 1.6 V (V_POR rising threshold) [p. 7].
   ALERT pull-up: 100 kΩ to V+ (external) or ESP-S3 internal WPU.
2. Wait 1.5 ms for internal POR sequence to complete [p. 12 §7.3.1; p. 7 t_RESET].
3. The chip auto-loads factory EEPROM config (default Configuration = 0x0220h):
     - Continuous conversion, 1 Hz, 8-sample averaging, Alert mode, POL=LOW.
4. (Optional) Verify presence: read Device_ID (pointer 0x0F) → expect 0x0117.
5. (Optional) Software reset for clean state:
     Write 0x01 = 0x0002   (Soft_Reset bit). Wait 2 ms.
6. (If non-default cycle desired) Write Configuration register:
     For wrist temp at 4 s cycle, 8-sample avg, Alert mode, Active-LOW ALERT, alert mode:
       MOD=00, CONV=101, AVG=01, T/nA=0, POL=0, DR/Alert=0
       → Configuration = 0x0AA0
     For data-ready interrupt pattern at 1 Hz, 8 avg:
       MOD=00, CONV=100, AVG=01, DR/Alert=1
       → Configuration = 0x0224
7. (Optional) Set THigh_Limit / TLow_Limit for fever/hypothermia alarms:
     For wrist temp upper alarm at 39 °C (4992 LSB = 0x1380):
       Write 0x02 = 0x1380
     For lower alarm at 32 °C (4096 LSB = 0x1000):
       Write 0x03 = 0x1000
8. (Optional) Load per-unit factory cal offset from NVS into Temp_Offset (0x07).
9. Wait at least one conversion cycle (1 s default; up to 16 s if CONV=111):
     **Temp_Result reads 0x8000 (= −256 °C) until first conversion completes.**
10. Poll Data_Ready in Configuration register, or watch ALERT pin (if DR/Alert=1):
     - Reading the temp register clears Data_Ready
11. Read 0x00 (Temp_Result) → convert: temp_C = raw / 128.0
```

**Critical:** the first read of Temp_Result returns **`0x8000` = −256 °C** until at least one conversion has completed (see WARN-04). FW must either wait the full conversion cycle, or check for this magic value and discard.

## Operation

### Reading temperature

```
S · 0x90 (W) · A · 0x00 · A · SR · 0x91 (R) · A · MSB · A · LSB · NA · P

raw = (int16_t)((MSB << 8) | LSB)
temp_C = raw / 128.0     // 1 LSB = 7.8125 m°C = 1/128 °C
```

Example: raw = 0x0C80 = 3200 → temp = 3200 / 128 = 25.000 °C [p. 13 Table 7-1].

### Operating modes [p. 14 §7.4]

| Mode | MOD[1:0] | Behavior | Use |
|---|---|---|---|
| **Continuous (CC)** | 00 (or 10) | Repeats conversion every CONV cycle | Default; "always-on" temp |
| **Shutdown (SD)** | 01 | Aborts running conversion, ~150 nA idle | Battery-saver between bursts |
| **One-Shot (OS)** | 11 | Performs one conversion, returns to SD | Best for tightly-controlled sample timing |

**Note:** MOD[1] cannot be stored in EEPROM [p. 27 footnote 2]. POR mode is always either continuous (00) or shutdown (01). One-shot requires runtime command.

### Temperature offset [p. 31 §7.6.9]

Useful for in-system calibration. After production / in-FW calibration, write a 16-bit two's complement offset (7.8125 m°C/LSB) to register 0x07. The chip adds it to every result after linearization. Example: if FW determines the chip reads 0.06 °C low, write +0.06 / (1/128) = 7.68 → 8 LSB → 0x0008 to Temp_Offset.

**Offset is NOT auto-stored in EEPROM** — write the same value at every boot from NVS, OR program it into EEPROM permanently via the EEPROM unlock sequence.

### ALERT pin modes

**Alert mode** (T/nA = 0, default) — **window detector**:
- HIGH_Alert flag set when T > THigh
- LOW_Alert flag set when T < TLow
- ALERT pin asserts (low, POL=0) when either flag is set
- Flags + ALERT clear when Configuration register is read (or via SMBus ALERT response)
- **Use case:** generic threshold detection (fever alarm + freeze alarm)

**Therm mode** (T/nA = 1) — **high-threshold with hysteresis**:
- HIGH_Alert set when T > THigh; cleared when T < TLow
- LOW_Alert always 0 (unused as flag, but as the hysteresis threshold)
- ALERT pin follows HIGH_Alert; does **not** clear on register read — only on temp dropping below TLow
- **Use case:** thermal-shutdown style ("alert until temp returns to safe band")

**Data-Ready mode** (DR/Alert = 1):
- ALERT pin reflects Data_Ready flag (asserts when new sample, clears on read of temp/config)
- **Use case:** zero-jitter ISR-driven sampling — ESP wakes on ALERT, reads temp, ALERT auto-clears

### EEPROM programming sequence [p. 18 §7.5.1.2; p. 19 Fig. 7-7]

1. **Unlock**: write 0x04 = `0x8000` (EUN = 1).
2. **Write desired value** to target register (Configuration, THigh, TLow, EEPROM1/2/3, Temp_Offset).
3. **Wait 7 ms** for the EEPROM cell to program.
4. Read EEPROM_UL (0x04) → check EEPROM_Busy bit → repeat wait if still 1.
5. **Repeat** for additional registers if desired.
6. **General-call reset**: send `0x00 · 0x06` to bus → triggers SW reset, reloads from EEPROM, **auto-locks EEPROM**.
7. (Optional) Read back the programmed registers to verify.

**EEPROM consumes 240 µA during programming** [p. 6 IEE]. Each program takes 7 ms × N writes — keep to a minimum (typically once per board during factory calibration).

## Interrupts

| Signal | Pin | Polarity | Behavior | Notes |
|---|---|---|---|---|
| ALERT | 3 | Programmable (POL bit) — default ACTIVE LOW | Configurable as alert flag OR data-ready flag (DR/Alert bit) | Open-drain — needs pull-up. |

**Pull-up:** **datasheet recommends 5 kΩ on SCL, SDA, ALERT** [p. 33 Fig. 8-1]. v7.2's 5.1 kΩ bus pulls match this exactly for SCL/SDA. **ALERT line needs its own pull-up** (separate from the bus). Likely needs to be added on the ESP-S3 GPIO side (10–100 kΩ external, or internal WPU enabled).

**Clear mechanism:**
- Alert mode (T/nA=0): read of Configuration register clears HIGH/LOW_Alert flags AND deasserts ALERT pin
- Therm mode (T/nA=1): no register read clears — only the temperature dropping below TLow clears
- Data-Ready mode (DR/Alert=1): read of Temp_Result OR Configuration clears Data_Ready AND deasserts ALERT

**v7.2:** ALERT GPIO routing not specified in v7.2 (assumed). If unrouted, no harm — leave the pin physically connected to a pull-up and ignore. If routed, can be used for "fever detected" wake-from-sleep. See Open Q3.

### Wearable budget — typical patterns

| Pattern | Avg current | Notes |
|---|---|---|
| Always shut down (sleep mode) | 0.15 µA | Background draw |
| Continuous 1 Hz, 8 avg (factory default) | 16 µA | "Live skin temp on watchface" |
| Continuous 4 s cycle, 8 avg | 4 µA | "Background skin-temp log" |
| Continuous 16 s cycle, 64 avg | 6 µA | "Highest accuracy, slow log" |
| One-shot per minute | <1 µA | "Wrist temp every minute" — explicit one-shot triggered by ESP |

**Recommendation for v7.2:** **4 s cycle (CONV=101), 8 avg (AVG=01)** = **4 µA on 3.2 V rail = 13 µW**. Skin temperature physiology doesn't need faster than 0.25 Hz. Negligible budget impact.

### Self-heating analysis

At default 16 µA average × 3.2 V = 51 µW dissipation. With θ_JA = 70.7 °C/W (DRV, board-mounted) → ΔT_self = 51 µW × 70.7 °C/W = **0.0036 °C** — **below the LSB resolution**. Negligible even for ±0.1 °C grade work.

In one-shot mode (135 µA × 3.2 V × 15.5 ms duty cycle = 6.7 µW avg) → ΔT < 0.001 °C. Even more negligible.

## Datasheet notes

- **Pointer register persists across STOPs** [p. 21 §7.5.3.1.3] — initialize pointer once, then poll temperature with minimal traffic.
- **Pointer upper 4 bits must be 0** [p. 22 Fig. 7-9 footnote] — sending e.g. `0xF0` instead of `0x00` violates protocol; chip may misbehave.
- **Soft_Reset bit auto-clears**, always reads back 0 [p. 28]. Don't poll it; trust the 2 ms wait.
- **Software reset takes 2 ms** [p. 28]; conventional 5 ms FW delay is safe.
- **General-call reset** (0x00 + 0x06) resets ALL TMP117s on the bus — useful for power-on cleanup. Also resets other I²C devices that respond to general call. Be careful in multi-sensor systems.
- **EEPROM endurance**: 50 000 writes (10 K min), 100-year retention (10 years min) [p. 7 §6.6]. Don't reprogram per-boot — store cal in NVS instead.
- **EEPROM1 and EEPROM3 contain factory unique IDs** — overwriting kills NIST traceability [p. 30, 32]. Use EEPROM2 for free scratch.
- **MOD[1] cannot be stored in EEPROM** [p. 27 footnote 2] — POR mode is constrained to CC or SD.
- **POR config = `0x0220`** [p. 27]: 1 Hz CC, 8 avg, alert mode, ALERT active-low → ready to use, no init needed for basic operation.
- **Temp_Result = `0x8000` (= −256 °C) until first conversion** [p. 13 Table 7-1; p. 26]. FW must wait or check for this magic.
- **Brownout detect at 1.1 V** [p. 7] — V+ falling through 1.1 V triggers a re-POR. Below operating range but above abs-min; transient brown-outs are tolerated.
- **Long-term stability ±0.03 °C** over 1000 hours at 150 °C [p. 6] — at wrist temperatures, drift is well below the per-LSB resolution.
- **NIST-traceable factory calibration** [p. 18] — TMP117 is **medical-grade** (meets ASTM E1112, ISO 80601-2-56 for electronic patient thermometers). For consumer wearable use, this is overkill but means the BOM trace is gold-standard.
- **EEPROM_Busy** mirrors in both Configuration register bit 12 and EEPROM_UL register bit 14. Either source works for polling.
- **Number of accuracy grades**: TMP117 (best, ±0.1 °C), TMP117M (medical, similar specs in slightly different ranges), TMP117N (lowest cost, ±0.1 °C from 25–50 °C). Confirm BOM line — likely just "TMP117" base grade.
- **Datasheet revision D (Sept 2022)** — current; v7.2 should be aligned with this revision.

| WARN-01 | **ALERT pin is open-drain, needs pull-up — and bus pull-ups don't help** | [p. 4 Table 5-1; p. 33 Fig. 8-1] | **HIGH** | The 5.1 kΩ pull-ups on SDA/SCL (bus 1) do NOT cover the ALERT line. ## Open questions

- **Q1 — Effective thermal time constant in worn form-factor.** Datasheet thermal mass + θ_JA gives ~360 ms in still air. On a wrist, with case thermal mass + skin contact, expect 10–60 s for full step response. **Action:** bench-characterize with a thermal step test (move from 25 °C to 35 °C ambient) once first silicon is in the assembled case.
- **Q2 — WSON thermal pad: soldered or floating?** For skin-temp accuracy, **soldered with via path to back of case** is preferred (better physical tracking). For absolute-accuracy specs as quoted, floating is what TI characterized. **Action:** mechanical design call — recommend **soldered**.
- **Q3 — ALERT GPIO routing in v7.2.** If routed, enables fever-alarm wake from deep-sleep without polling. If unrouted, leave pin with a pull-up (5 kΩ as datasheet recommends, or 100 kΩ ext / internal WPU) and ignore in FW. **Action:** schematic review.
- **Q4 — Calibration strategy.** Should each board be factory-calibrated against a reference (e.g., NIST-traceable RTD bath) and the offset stored in NVS (or in TMP117's own EEPROM via Temp_Offset register)? **Action:** product decision based on accuracy target. For consumer wearable, factory cal is overkill; the TMP117's own factory cal is good enough.
- **Q5 — Default conversion cycle for wrist temp use.** Recommend **CONV=101 (4 s), AVG=01 (8 avg) → 4 µA average**. Faster than physiological change, much slower than display refresh, very low power. **Action:** confirm with product owner — they may want 1 Hz "live" reading for UX.
- **Q6 — Use of EEPROM2 for board serial number.** EEPROM2 is free 16-bit user scratch. Could store a board-revision tag or simple serial number for production tracking. **Action:** optional production-engineering decision.
- **Q7 — Therm mode use case.** Therm mode (T/nA=1) is genuinely useful for "fever alarm" with hysteresis (no flapping at threshold). **Recommend** for fever-detection use case; not necessary for general logging. **Action:** FW design call.
