### Transaction formats [p. 6 Fig. 9]

**Send (write) Word:**
```
S · 0x20 (W) · A · cmd_code (1 byte) · A · data_LSB · A · data_MSB · A · P
```

**Receive (read) Word:**
```
S · 0x20 (W) · A · cmd_code · A · SR · 0x21 (R) · A · data_LSB · A · data_MSB · N · P
```

**Critical:** byte order is **LSB first, MSB second** [p. 6 Fig. 9 and Send Byte / Receive Byte panels]. Many host I²C drivers default to MSB-first — code the VEML6030 register access explicitly, or wrong values will be read.

## Registers (firmware-critical) — all 16-bit [p. 7 Register Addresses]

Six user-accessible commands + one ID register. All R/W except status/data registers.

| Cmd | Name | R/W | Default | Bits | Purpose | Source |
|---|---|---|---|---|---|---|
| `0x00` | **ALS_CONF** | R/W | **`0x0001`** | 12:11 GAIN, 9:6 IT, 5:4 PERS, 1 INT_EN, 0 SD | Mode/config + sleep | [p. 7 Table 1] |
| `0x01` | ALS_WH | R/W | `0x0000` | 15:0 | High threshold (raw counts) | [p. 8 Table 2] |
| `0x02` | ALS_WL | R/W | `0x0000` | 15:0 | Low threshold (raw counts) | [p. 8 Table 3] |
| `0x03` | PSM | R/W | `0x0000` | 2:1 PSM mode, 0 PSM_EN | Power-saving (sleep between samples) | [p. 8 Table 4] |
| `0x04` | ALS | R | — | 15:0 | **ALS channel** raw data (visible-band) | [p. 8 Table 5] |
| `0x05` | WHITE | R | — | 15:0 | WHITE channel raw data (broader spectrum incl. IR) | [p. 8 Table 6] |
| `0x06` | ALS_INT | R | — | bit15 = int_th_low, bit14 = int_th_high | Interrupt status (read-clears via reading?) | [p. 9 Table 7] |
| `0x07` | ID | R | — | 15:8 = address-option ID, 7:0 = 0x81 device ID | Device identification (WHO_AM_I) | [p. 9 Table 8] |

**ID register value:** at v7.2's ADDR=GND → reads **`0xC481`** (low byte 0x81 = device ID, high byte 0xC4 = "address option 0x20" identifier). If ADDR=VDD → `0xD481`. **Use this for boot-time presence check.** [p. 9 Table 8]

### ALS_CONF bit fields (cmd 0x00) [p. 7 Table 1]

- `[15:13]` Reserved — write `000b`.
- `[12:11]` **ALS_GAIN**:
  - `00` = ×1 (default after first wake)
  - `01` = ×2 (best low-light SNR)
  - `10` = ×1/8 (highest range)
  - `11` = ×1/4
- `[10]` Reserved — write `0b`.
- `[9:6]` **ALS_IT** (integration time):
  - `1100` = 25 ms (fastest, lowest resolution)
  - `1000` = 50 ms
  - `0000` = 100 ms (default after first wake)
  - `0001` = 200 ms
  - `0010` = 400 ms
  - `0011` = 800 ms (highest resolution, slowest)
- `[5:4]` **ALS_PERS** (persistence — N consecutive out-of-window readings to trigger INT):
  - `00` = 1, `01` = 2, `10` = 4, `11` = 8
- `[3:2]` Reserved — write `00b`.
- `[1]` **ALS_INT_EN**: 0 = INT disabled, 1 = INT enabled (fires when ALS crosses ALS_WH / ALS_WL with PERS satisfied).
- `[0]` **ALS_SD** (Shut Down): **1 = device OFF (default at power-up)**, 0 = device ON.

### PSM bit fields (cmd 0x03) [p. 8 Table 4]

- `[15:3]` Reserved — write `0000 0000 0000 0`.
- `[2:1]` **PSM mode** (sleep duration between conversions):
  - `00` = Mode 1 (shortest sleep, highest sample rate, highest power)
  - `01` = Mode 2
  - `10` = Mode 3
  - `11` = Mode 4 (longest sleep, lowest sample rate, lowest power)
- `[0]` **PSM_EN**: 0 = continuous (no PSM), 1 = PSM enabled.

### Sensitivity / Resolution (lx per LSB) [computed from p. 2 + p. 9]

Resolution at default ALS_GAIN = x2:

| ALS_IT | lx / count | Max readable (65535 × res) | Notes |
|---|---|---|---|
| 25 ms | 0.1344 | 8806 lx | Combined with gain=1/8 → max 140 000 lx |
| 50 ms | 0.0672 | 4404 lx | |
| 100 ms | 0.0336 | 2202 lx | |
| 200 ms | 0.0168 | 1101 lx | |
| 400 ms | 0.0084 | 550 lx | |
| 800 ms | **0.0042** | 275 lx | Maximum sensitivity — only useful for dim rooms |

Resolution scales with **(1 / gain) × (100 ms / IT)** relative to the gain=×1, IT=100ms baseline of ≈ 0.0576 lx/count [implied by ratio analysis of p. 9 table]. Vishay's application note ("Designing the VEML6030 Into an Application") has the full lookup table [p. 7 ref]; treat the simple ratio rule as authoritative within ±5 %.

## Initialization sequence

[Synthesized from p. 7 Table 1 + p. 6 Application Circuit]

```
1. (Hardware) 3.2 V rail comes up; bus-1 pull-ups active; ADDR pin strapped to GND.
2. (Optional) Verify presence: read cmd 0x07 → expect 0xC481.
3. Default state is SHUTDOWN (ALS_SD=1, register 0x00 default = 0x0001).
   Wake the device:
     Write 0x00 = 0x0000   (ALS_GAIN=x1, ALS_IT=100ms, ALS_PERS=1, ALS_INT_EN=0, ALS_SD=0)
   — pick GAIN/IT for your use case; values above give 0.0576 lx/bit, 0–3776 lx range.
4. Wait at least ALS_IT × persistence (worst case ~800 ms × 8 = 6.4 s for full settling
   at max IT/PERS). For default 100 ms IT, **wait ≥ 400 ms** before first ALS read to
   guarantee a stable post-startup reading [p. 1 + general ALS startup convention].
5. (Optional) Configure interrupt:
     a. Set ALS_WH = high threshold (in raw counts at chosen gain/IT)
     b. Set ALS_WL = low threshold
     c. Write 0x00 with bit 1 (ALS_INT_EN) = 1 and chosen ALS_PERS
6. (Optional) Enable Power-Saving Mode:
     Write 0x03 = (mode << 1) | 1   — adds an idle window between conversions.
7. Ready to poll cmd 0x04 (ALS) or 0x05 (WHITE) for data.
```

**Critical:** the device boots in shutdown. **A naïve "read ALS register without configuring first" returns the last stored value (auto-memorized — see Datasheet notes), not a live reading.** Always do step 3 before trusting data. [p. 9 §Auto-Memorization]

## Operation

### Reading ALS data [p. 8 Table 5]

```
S · 0x20 (W) · A · 0x04 · A · SR · 0x21 (R) · A · byte_LSB · A · byte_MSB · N · P

raw_counts = (byte_MSB << 8) | byte_LSB    // BIG-endian assembly from LSB-first wire order
lx = raw_counts × resolution_lx_per_count
```

**WHITE channel** (cmd 0x05) is read identically — useful for daylight vs. IR-heavy source disambiguation, and as a sanity-check denominator (if WHITE >> ALS, source is IR-dominated and the visible-light reading may be biased).

### Auto-ranging (firmware algorithm — NOT in hardware) [WARN-01]

The chip does not auto-range. A reasonable FW state machine:

```
fn read_lx(target_gain, target_IT) -> (lx, gain_used, IT_used):
  raw = i2c_read16(0x04)
  if raw > 52000:          # ~80% of full scale → reduce sensitivity
    if target_IT > 25 ms:
      target_IT /= 2
    elif target_gain != x1/8:
      target_gain = next_lower(target_gain)
    else:
      return (raw × res(gain, IT), SATURATED_FLAG)
    write_config(target_gain, target_IT)
    sleep(target_IT × 1.5)        # let new integration complete
    return read_lx(target_gain, target_IT)   # recursive retry
  if raw < 256 and (gain != x2 or IT != 800ms):    # < ~0.4% FS → expand sensitivity
    expand(target_gain, target_IT)
    sleep(target_IT × 1.5)
    return read_lx(target_gain, target_IT)
  return (raw × res(target_gain, target_IT), target_gain, target_IT)
```

This belongs in the firmware ALS driver. v7.2's "auto-brightness" feature requires this loop. **Document this gap so audit fixes the v7.2 wording from "auto-ranging" to "firmware auto-ranging algorithm".** [WARN-01]

### Interrupt usage [p. 7 Table 1 + p. 9 Table 7]

- Set ALS_WH and ALS_WL to define the in-band window.
- Enable interrupts (ALS_INT_EN = 1) and pick persistence (number of consecutive out-of-window samples needed before INT asserts).
- On INT-LOW: read cmd 0x06 (ALS_INT). Bit 15 = int_th_low (reading went below ALS_WL); bit 14 = int_th_high (reading went above ALS_WH).
- **Interrupt clearing mechanism** is not explicitly documented in this datasheet — the application note describes it as "read ALS_INT to clear" (typical Vishay pattern). [datasheet silent — confirm with Vishay AN or bench test] See Open Q3.

### Power-Saving Mode (PSM) [p. 9 §Refresh Time + Table 4]

When PSM_EN = 1, the chip integrates for ALS_IT, then sleeps for (refresh_time − ALS_IT), then integrates again. Lower current at the cost of slower refresh:

| ALS_IT | PSM Mode | Refresh time | I_DD typ | Resolution (gain ×2) |
|---|---|---|---|---|
| 100 ms | Mode 1 | 600 ms | 8 µA | 0.0336 lx/bit |
| 100 ms | Mode 2 | 1100 ms | 5 µA | 0.0336 lx/bit |
| 100 ms | Mode 3 | 2100 ms | 3 µA | 0.0336 lx/bit |
| 100 ms | **Mode 4** | **4100 ms** | **2 µA** | 0.0336 lx/bit |
| 200 ms | Mode 1 | 700 ms | 13 µA | 0.0168 |
| 200 ms | Mode 4 | 4200 ms | 3 µA | 0.0168 |
| 400 ms | Mode 1 | 900 ms | 20 µA | 0.0084 |
| 400 ms | Mode 4 | 4400 ms | 5 µA | 0.0084 |
| 800 ms | Mode 1 | 1300 ms | 28 µA | 0.0042 |
| 800 ms | Mode 4 | 4800 ms | 8 µA | 0.0042 |
| any IT | PSM disabled (continuous) | ≈ IT | **45 µA** | — |

**Recommendation for wearable:** **ALS_IT = 100 ms, PSM Mode 4** (2 µA, 4 Hz worst-case refresh). For auto-brightness, a 4 s refresh is fast enough — display brightness should change slowly to avoid visible chatter. If FW wants snappier response (e.g., user holds device toward sun), switch to PSM disabled momentarily for the burst, then return.

## Interrupts

| Signal | Pin | Polarity | Trigger | Notes |
|---|---|---|---|---|
| INT | Pin 3 (open-drain, active LOW) | Active LOW | ALS reading crosses out of [ALS_WL, ALS_WH] for PERS consecutive samples | Vishay-recommended pull-up: 10 kΩ–100 kΩ to V_DD [p. 6 Notes] |

**De-assertion:** datasheet does not explicitly state the clear mechanism for the INT line — Vishay's app note (`Designing the VEML6030 Into an Application`) is the cited authority. The convention for VEML6030/VEML7700 family is **read of cmd 0x06 (ALS_INT) clears the latched flags**, after which INT goes high-Z again. **Bench-confirm during bring-up.** [Open Q3]

**Latency:** with PERS=1 and IT=100 ms, worst-case latency is one integration cycle + one I²C round-trip ≈ 100–150 ms. For deep-sleep wake from a bright-light event, this is acceptable for an auto-brightness use case (no human perceives 150 ms screen-on lag).

**Wake-from-deep-sleep on INT:** if v7.2 routes INT to an ESP-S3 RTC-GPIO with WPU enabled, the device can wake the MCU on threshold crossing. Useful for "screen wake on lift-to-bright" gesture if combined with the IMU. Not a primary wake source — primary wake is touch + IMU + crown. ALS-wake is opportunistic.

### System budget (3.2 V rail contribution)

- **Sleeping (between sessions, ALS shut down):** 0.5 µA — essentially free.
- **Normal idle (PSM Mode 4, IT=100ms):** 2 µA — 4-second refresh, fine for auto-brightness.
- **Active auto-ranging burst (PSM disabled briefly):** 45 µA × 200 ms ≈ 9 µC = average <0.5 µA if done once per minute.

**Total contribution to wearable budget: ≤ 5 µA typical, ≤ 50 µA worst-case during auto-range bursts.** Negligible vs. the ~10–50 mA range that defines the active runtime.

## Datasheet notes

- **Auto-memorization** [p. 9 §Auto-Memorization]: the chip remembers the **last ALS reading taken before entering shutdown**. After waking (or even while still in SD=1), reading cmd 0x04 returns that stale frozen value. On next conversion the value refreshes. **Implication for FW:** if you cycle the chip in-and-out of shutdown to save power between reads, the *first* read after wake is the previous reading, not a fresh one. Always wait one IT period after waking before trusting the data.
- **Floor life 72 h, MSL 4** [p. 1] — sensitive to moisture during PCB assembly. Must be baked or used within 72 h of opening the moisture-barrier bag. Production matters.
- **Spectral response** [p. 5 Fig. 5]: ALS channel reasonably matches CIE photopic V(λ) but slightly broader on the red side. The "Refresh time × resolution" table assumes white-LED reference — readings under red-shifted sources (incandescent, warm LED) will be slightly under-reported relative to "true lux".
- **WHITE channel** [p. 5 Fig. 6]: extends well into NIR (peak ~600–800 nm, response out to 1000+ nm). Useful for sun/incandescent detection. ALS/WHITE ratio is a classic IR-content proxy.
- **Angular response** [p. 5 Fig. 7]: ±60° half-angle, roughly Lambertian (cosine-weighted). The package is a "naked" optical aperture; placement under a glass overlay needs trans/reflection accounting.
- **Auto-ranging is NOT built in** [p. 7 Table 1]. Common misconception across hobby boards.
- **Junction temp max 110 °C** [p. 2 Abs. Max]. With 50 mW P_tot dissipation cap, the chip is thermally limited at high light levels only when continuously transmitting (n/a — this is a sensor). For normal use, fully thermally happy.
- **No pull-down/pull-up on ADDR pin specified** — datasheet does not state ADDR has an internal resistor. v7.2 must hard-strap to GND.
- **No internal reset register** — there's no software reset command. To clean-slate the chip, use SD=1 → wait → write fresh CONF → SD=0.

## Warnings & Errata

| ID | Title | Source | Severity | Description / Mitigation |
|---|---|---|---|---|
| WARN-01 | **No hardware auto-ranging — FW must implement it** | [p. 7 Table 1] | **HIGH** | The kickoff doc and v7.2 imply "auto-ranging" is a chip feature. **It is not.** Gain and integration time are pure manual register writes. **Mitigation:** implement the auto-range loop (see Operation §Auto-ranging) in the ALS driver. Without it, the FW will saturate above ~3000 lx (default config gain=×1, IT=100ms gives ~3777 lx max). For an auto-brightness algorithm, this means anything brighter than a bright indoor lamp will read as "max" — useless outside. **Update v7.2 wording** from "auto-ranging" to "firmware auto-ranging algorithm". |
| WARN-02 | **Device boots in SHUTDOWN (ALS_SD = 1 by default)** | [p. 7 Table 1 Note] | **HIGH** | "Command code 0 default value is 01 = devices is shut down". Any FW that powers up and immediately reads cmd 0x04 will get a **stale auto-memorized value**, not a live measurement. **Mitigation:** boot sequence must always include the configuration write (cmd 0x00 with SD=0) before relying on data. Add an assertion: after writing config, read it back to confirm SD=0. |
| WARN-03 | **INT pin is open-drain, needs pull-up; v7.2 doesn't specify** | [p. 6 Application Circuit notes] | **MED** | If INT GPIO floats with WPU disabled, false interrupts (or none at all) are possible. **Mitigation:** (a) confirm INT GPIO routing in v7.2 schematic, (b) add external 100 kΩ pull-up to 3V3 (negligible 30 nA draw) **or** enable ESP-S3 internal WPU on that GPIO in init. | WARN-04 | **Auto-memorized stale data after shutdown wake** | [p. 9 §Auto-Memorization] | MED | After ALS_SD = 0 → 1 cycle, the first cmd 0x04 read returns the *previous* measurement, not a new one. **Mitigation:** wait at least one IT period (100 ms minimum, 800 ms max) after waking from shutdown before trusting the ALS register. The VEML6030 sends **data_LSB then data_MSB**. **Mitigation:** code the driver as two explicit 8-bit reads, then assemble `(MSB << 8) | LSB`.
