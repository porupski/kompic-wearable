## Critical findings (read this first)

Two hardware-architecture-level conflicts vs. v7.2 / the porting doc. Both must be resolved before silicon:

### 1. VDD on 3V3 will DESTROY the chip [p. 2]

**Absolute maximum rating: V_DD to GND = -0.3 V to +2.2 V.** Operating range = 1.7–2.0 V (typ 1.8 V) [p. 2, Electrical Characteristics].

v7.2 and `MAX30101_2026-06-11_iv7.1.f0.0.md` line 47 say: *"3V3 | VDD | TPS62840 buck, always-on"*. Powering VDD with 3.3 V exceeds the absolute maximum rating by **+1.1 V** and will damage the chip the moment power is applied.

**Required hardware fix (board change before fab):** add a 1.8 V LDO (or a 1.8 V output from the second TPS62840 channel — but iv7.1 only has one buck on this rail). VDD draws ~600 µA active / 0.7 µA shutdown so a tiny SOT23 LDO suffices.

### 2. Green LED cannot operate from 3V3 [p. 2]

**V_LED+ for Green LED is specified MIN = 4.5 V**, TYP 5.0 V, MAX 5.5 V [p. 2 — PSRR_LED row]. Red/IR LEDs accept VLED+ ≥ 3.1 V, but **Green needs ≥ 4.5 V**.

v7.2 implies LED_VCC is shared with the 3.3 V buck rail (per the porting doc line 47). Two consequences:
- **Green channel (LED3 / LED4) will not work at all** on a 3V3 LED rail. The `setup_multi_led_mode()` path in the driver is dead silicon until LED_VCC is rewired.
- **Red and IR will work at 3V3** (within the 3.1–5.0 V "guaranteed by PSRR" range), but with reduced headroom and possibly lower max LED current at the high end of the 50 mA scale.

**Required hardware fix:** wire V_LED+ to the BQ25619 boost output (PMID, 5.0 V typ when boost is active), not to the 3V3 buck. The BQ25619 in 20.13 already exposes PMID at 5.0 V (BOOSTV=10) up to 1 A. Boost must be enabled (BST_CONFIG=1 in BQ25619 REG01[5]) whenever the MAX30101 LEDs are on. See 20.13 for the boost-arbitration policy.

### 3. Porting-log spec discrepancies to confirm

- `MAX30101_2026-06-11_iv7.1.f0.0.md` line 167 says *"PA=0x1F maps to ~12 mA"*. **Datasheet Table 8 [p. 20] says 0x1F = 6.2 mA** (step ~0.2 mA/LSB, code 0x3F = 12.6 mA). The porting doc figure is 2× the datasheet. Probably mis-keyed against the MAX30102 era LED current table (which had a different mapping).
- `setup_hr_mode()` uses *"SMP_AVE=4 (25 Hz effective)"* [porting doc line 100]. **SMP_AVE register value 0b100 = 16 samples averaged** per [Table 3, p. 19]; with SR=100 Hz that gives 6.25 Hz effective, not 25 Hz. If the intent is 25 Hz effective, set SMP_AVE = 0b010 (= 4 samples averaged). Clarify before bring-up — the comment and the code may be inconsistent.

### Firmware-critical bit fields

**INT_STATUS_1 (0x00)** [p. 13]
- `[7] A_FULL` — FIFO almost full (level set by FIFO_A_FULL[3:0])
- `[6] PPG_RDY` — new sample in FIFO (data ready)
- `[5] ALC_OVF` — ambient-light cancellation overflow
- `[0] PWR_RDY` — power-up / brown-out recovery flag. **Cannot be masked.** A 1 here means the IC just powered up and ALL config registers are at POR.

*Reading INT_STATUS_1 (or reading the register that triggered the interrupt) clears the /INT pin and the latched bits.* [p. 13]

**INT_ENABLE_1 (0x02)** [p. 14]
- `[7] A_FULL_EN` — set to enable A_FULL interrupt
- `[6] PPG_RDY_EN` — set to enable PPG_RDY interrupt (typically NOT set — too noisy at full SR)
- `[5] ALC_OVF_EN` — set to enable ALC overflow interrupt

**FIFO_CONFIG (0x08)** [p. 18]
- `[7:5] SMP_AVE[2:0]` — Sample averaging:
  - 000 = 1, 001 = 2, 010 = 4, 011 = 8, 100 = 16, 101/110/111 = 32 [Table 3, p. 18]
- `[4] FIFO_ROLLOVER_EN` — 0 = stop writing when full (default), 1 = roll over and overwrite
- `[3:0] FIFO_A_FULL[3:0]` — Almost-full level. 0x0 = INT at FIFO full (32 unread), 0xF = INT when 17 unread (= 15 empty slots remain). [Table p. 18]

**MODE_CONFIG (0x09)** [p. 18, 19]
- `[7] SHDN` — 1 = power-save (registers retained, /INT cleared). 0 = active.
- `[6] RESET` — 1 = software POR (all regs to default; auto-clears; does NOT trigger PWR_RDY)
- `[2:0] MODE[2:0]` — Mode select:
  - 010 = Heart Rate (Red only)
  - 011 = SpO2 (Red + IR)
  - 111 = Multi-LED (Green, Red, and/or IR per SLOTx config)
  - Others = "Do not use"

**SPO2_CONFIG (0x0A)** [p. 19]
- `[6:5] SPO2_ADC_RGE[1:0]` — ADC full-scale (18-bit res):
  - 00 = 2048 nA (LSB 7.81 pA), 01 = 4096 nA (15.63 pA), 10 = 8192 nA (31.25 pA), 11 = 16384 nA (62.5 pA) [Table 5, p. 19]
- `[4:2] SPO2_SR[2:0]` — sample rate (samples per second):
  - 000=50, 001=100, 010=200, 011=400, 100=800, 101=1000, 110=1600, 111=3200 [Table 6, p. 19]
- `[1:0] LED_PW[1:0]` — pulse width / ADC resolution [Table 7, p. 20]:
  - 00 = 69 µs / 15-bit
  - 01 = 118 µs / 16-bit
  - 10 = 215 µs / 17-bit
  - 11 = 411 µs / 18-bit

**LEDx_PA (0x0C–0x0F)** [p. 20]
- 8-bit current code, **step ~0.2 mA/LSB**, max 0xFF = ~51.0 mA. Datasheet warns: *"Actual measured LED current for each part can vary significantly due to the trimming methodology."* So 0x1F = 6.2 mA typ, 0x3F = 12.6 mA typ, 0x7F = 25.4 mA typ.

**MULTI_LED_CTRL_x (0x11, 0x12)** [p. 20, 21 Table 9]
- `[6:4] SLOTx (high slot)`, `[2:0] SLOTx (low slot)` — slot LED select:
  - 000 = slot disabled
  - 001 = LED1 (Red)
  - 010 = LED2 (IR)
  - 011 = LED3 (Green, current set by LED3_PA)
  - (LED4_PA also drives green LED when SLOT = 011 in the LED4 slot of CTRL_2 high nibble — both LED3 and LED4 PA registers wire to the same green die [p. 21 footnote])
  - 100 = disabled / 101–111 = RESERVED

**TEMP_CONFIG (0x21)** [p. 22]
- `[0] TEMP_EN` — set 1 to trigger a single die-temp conversion. Self-clears when done. Conversion takes ~29 ms [p. 4 T_T row]. DIE_TEMP_RDY interrupt fires when complete; read TINT + TFRAC to compose value (TINT in 2's complement integer °C; TFRAC in 0.0625 °C/LSB, **always added positively** — e.g., TINT=0x80 (−128) + TFRAC=0x08 (+0.5) = −127.5 °C [p. 21]).

## Initialization sequence [p. 24, derived from Figures 4, 5, 6]

```
Power-on order recommended: VDD up FIRST, then VLED+ [p. 24, Fig 6]
(Datasheet permits any sequence — the chip is tolerant — but VDD-first
gives clean PWR_RDY assertion.)

1. After VDD stable, read INT_STATUS_1 (0x00) — this clears PWR_RDY.
2. Verify PART_ID at 0xFF reads 0x15. [p. 13]
3. Soft-reset: MODE_CONFIG (0x09) = 0x40 (RESET=1). Poll until bit auto-clears (~< 1 ms typ). [p. 18]
4. Clear FIFO pointers: write 0x00 to 0x04 (WR_PTR), 0x05 (OVF), 0x06 (RD_PTR). [p. 16]
5. Configure FIFO: FIFO_CONFIG (0x08) =
     (SMP_AVE << 5) | (rollover_en << 4) | FIFO_A_FULL
   Example for 100 Hz SpO2 / 4-sample average / int-when-15-unread:
     SMP_AVE=010, rollover=1, A_FULL=0x11 (17 unread → 15 empty slots remain)
     -> 0x51
6. SpO2 config (0x0A): set ADC_RGE / SR / LED_PW
   Example for 17-bit / 100 sps / range 4096 nA:
     SPO2_ADC_RGE=01, SPO2_SR=001, LED_PW=10  ->  0x29
7. Set LED currents:
     LED1_PA (0x0C) = 0x3F  (~12.6 mA Red)  ← matches porting-doc "~12 mA" intent
     LED2_PA (0x0D) = 0x3F  (~12.6 mA IR)
     LED3_PA (0x0E) = 0x00  (Green off; Phase 3 SpO2 only)
8. Enable interrupts: INT_ENABLE_1 (0x02) =
     A_FULL_EN=1, ALC_OVF_EN=1, PPG_RDY_EN=0   ->  0xA0
9. Set MODE: MODE_CONFIG (0x09) =
     SHDN=0, RESET=0, MODE=011 (SpO2)  ->  0x03
10. Read INT_STATUS_1 (0x00) again to flush any boot-time latched events.
11. FIFO begins filling. After ~150 ms (settling) data is reliable.
```

**Wake-from-shutdown:** Clear bit 7 of MODE_CONFIG (write a fresh MODE_CONFIG byte). Settling ~10 ms before first valid sample [porting-doc bench convention].

**Settling:** Datasheet does not give an explicit "first-sample-valid" delay. The porting doc carries a 10 ms settle (Phase 14 fix) — keep it.

## Operation

### Modes [p. 19 Table 4]

| MODE[2:0] | Mode | Active channels | Bytes per FIFO sample |
|---|---|---|---|
| 010 | Heart Rate | Red only | 3 |
| 011 | SpO2 | Red + IR | 6 |
| 111 | Multi-LED | up to 4 slots × 3 bytes | 3, 6, 9, or 12 |
| others | Do not use | — | — |

### FIFO mechanics [p. 14–17]

- 32 samples deep. Each sample = 3 bytes per active LED channel (Red+IR = 6 bytes/sample in SpO2 mode).
- Total memory = 32 × 9 bytes = 288 bytes (worst case, Multi-LED with 3 slots).
- Sample is **left-justified** in 3 bytes; MSB always at bit 17 regardless of ADC resolution (15/16/17/18 bit). FIFO_DATA[18-23] unused.
- For SpO2 mode, one sample = 6 bytes (Byte1 = LED1_MSB, Byte2 = LED1_MID, Byte3 = LED1_LSB, Byte4–6 = LED2). [p. 15 Table 2]
- For Multi-LED 3-slot mode (Red+IR+Green), one sample = 9 bytes.

**Reading the FIFO** [p. 14–17]:
1. (Optional) Read FIFO_WR_PTR (0x04) and FIFO_RD_PTR (0x06). NUM_AVAILABLE = (WR_PTR − RD_PTR) mod 32. Handle wrap.
2. Burst-read FIFO_DATA (0x07) for NUM_SAMPLES × (3 × num_channels) bytes. The read pointer auto-advances by one position per *sample*, not per byte.
3. (Optional) Write FIFO_RD_PTR (0x06) to confirm or correct.

**Burst read timing at 400 kHz:** 9-byte burst (Multi-LED) = address byte + 9 data bytes = 10 bytes × 9 bit-times (+ overhead) ≈ ~250 µs of bus time per sample, or ~7.5 ms wire time for a full 32-sample drain in Multi-LED mode. SpO2 (6 bytes/sample) is ~170 µs/sample, ~5.5 ms for a full drain.

### FIFO settling

Datasheet does not specify FIFO-fill settling beyond the ADC integration time + slot-timing. The porting-doc 10 ms wake-up settle is empirical / safe.

### Slot timing in Multi-LED mode [p. 22 Table 11]

| LED_PW (µs) | Slot timing (µs) | Channel-channel rising edge (µs) |
|---|---|---|
| 69 | 358 | 427 |
| 118 | 407 | 525 |
| 215 | 505 | 720 |
| 411 | 696 | 1107 |

**Implication:** Max sample rate depends on LED_PW because all enabled channels must fit within one 1/SR period. Datasheet enforces this internally — if SR is set too high for LED_PW, the chip clamps to the highest legal SR per [Table 15 / Table 16, p. 29, 30].

### Allowed (SR, LED_PW) combos [p. 29 Table 15, p. 30 Table 16]

In **SpO2 mode** (Red + IR), LED_PW = 411 µs limits SR ≤ 400 sps. LED_PW = 69 µs allows up to 3200 sps. The 100 Hz / 215 µs combo we use is in the green zone.

In **HR mode** (single LED), LED_PW = 411 µs allows up to 1000 sps; LED_PW = 69 µs allows the full 3200 sps.

### Die temperature read sequence [p. 22, 23 Fig 4]

1. Set DIE_TEMP_RDY_EN in INT_ENABLE_2 (0x03) = 0x02.
2. Trigger conversion: TEMP_CONFIG (0x21) = 0x01. Self-clears when done.
3. Wait for DIE_TEMP_RDY interrupt (~29 ms typ), OR poll INT_STATUS_2 (0x01) bit 1.
4. Read TINT (0x1F) and TFRAC (0x20). Compose T_measured = TINT (signed °C) + TFRAC × 0.0625. **Fraction adds POSITIVELY even when integer is negative** [p. 21].
5. Reading TINT or TFRAC also clears the DIE_TEMP_RDY interrupt [p. 13].

**Accuracy:** ±1 °C at T_A = 25 °C [p. 4]. Range −40 to +85 °C. Resolution 0.0625 °C [p. 4].

## Interrupts

The MAX30101 exposes **one /INT pin** (pin 13) — open-drain, active-LOW, asserted level (NOT pulsed). The pin stays LOW from when the interrupt arms to when the host clears it. [p. 13, 30]

| Source | Bit | Register | Cleared by |
|---|---|---|---|
| A_FULL | INT_STATUS_1[7] | 0x00 | Reading 0x00 |
| PPG_RDY | INT_STATUS_1[6] | 0x00 | Reading 0x00 **or** reading FIFO_DATA (0x07) |
| ALC_OVF | INT_STATUS_1[5] | 0x00 | Reading 0x00 |
| PWR_RDY | INT_STATUS_1[0] | 0x00 | Reading 0x00. **Cannot be masked.** |
| DIE_TEMP_RDY | INT_STATUS_2[1] | 0x01 | Reading 0x01 **or** reading TFRAC (0x20) |

**Polarity:** Active-LOW open-drain. Pull-up resistor (typ 4.7 kΩ) required to a voltage rail up to +5 V [p. 30]. **The pin can be pulled up to VDDIO (3V3) on the ESP side** — this is independent of VDD (which must stay 1.8 V).

**Clearing semantics:** The interrupt bit is latched until the register that holds it is read. Reading the relevant register also drives /INT back HIGH. There is no auto-clear timer.

**Polling FIFO with PPG_RDY masked:** Reading FIFO_DATA *also* clears PPG_RDY [p. 13] — so a polling driver that drains the FIFO via burst-read automatically de-asserts PPG_RDY without an explicit INT_STATUS_1 read. Convenient for the current driver design.

### Calculated currents for Kompic operation

LED-on duty cycle = (LED_PW) × (samples/sec) × (# channels). For SpO2 @ 100 sps, 215 µs PW, 2 LEDs:

- Duty cycle = 215 µs × 100 × 2 = 0.043 = 4.3 %
- LED average current per channel @ 12.6 mA peak (PA=0x3F) = 0.0215 × 100 × 12.6 = ~27 µA per channel from V_LED+ ... wait this is wrong. Let me re-check.

Actually, average current = peak × duty = 12.6 mA × (215 µs × 100 sps) = 12.6 × 0.0215 = **0.27 mA average per LED** from V_LED+.

So with Red + IR both at PA=0x3F, SR=100 Hz, PW=215 µs:

| Rail | Component | Current |
|---|---|---|
| V_DD (1.8 V) | I_DD analog | ~0.6 mA |
| V_LED+ (5.0 V) | Red LED average | ~0.27 mA |
| V_LED+ (5.0 V) | IR LED average | ~0.27 mA |
| V_LED+ (5.0 V) | LED-driver overhead | ~0.5 mA (estimated; datasheet implicit via I_DD = supply-only spec, not driver overhead) |
| Total V_LED+ from boost | | **~1.0 mA average** |
| Total V_DD | | **~0.6 mA** |

**The porting-doc "~25 mA average" estimate [line 162] is off by ~25×.** That figure would only apply at much higher PA codes (~PA=0xFF → 50 mA peak, ~1 mA average per LED) AND/OR much longer pulse widths.

**Shutdown total:** < 1 µA on V_DD; V_LED+ shutdown current depends on the LED rail source (typically I_LED_SHDN ≈ 0.07–0.13 µA on a 4.75 V V_LED+ rail per [p. 7 graph], which is negligible).

**Calculation notes:** The supply-current rows in [p. 2] are the chip's *analog* current. LED current is separate — it comes from V_LED+ and depends on PA setting, SR, and PW. Total system current = I_DD (V_DD) + sum_of_LEDs(PA, SR, PW) (V_LED+).

## Datasheet notes

- **OLGA package is open to dust/liquid** [p. 29]. Should be the last component placed on the board; no liquid cleaning; no baking. AN 6381 (Maxim handling AN) describes the assembly process.
- **Internal die-temperature sensor** has tens-of-µs thermal time constant — meaning the LED die heats up nearly instantly during a pulse. Wavelength shifts with current. [Table 17, p. 30] shows Red-LED temperature-rise estimates per current setting and duty cycle. Used by SpO2 algorithm to compensate Red wavelength.
- **DC ambient-light rejection** ("ALR" row, p. 3) is 2 counts under direct 100 K lux sunlight at PA=0x3F. The ALC (Ambient-Light Cancellation) circuit cancels up to 200 µA of ambient current [p. 11].
- **Photodiode QE peak** ~70 % around 660 nm; usable spectral range 640–980 nm [p. 4 Photodetector Characteristics, p. 9 QE plot].
- **Green LED forward voltage** is ~3.3 V at I_LED = 50 mA [p. 4]. At 12.6 mA the VF is ~3.0 V. **This is why VLED+ must be ≥ 4.5 V for green** — the chip needs ~1.5 V headroom over VF for the LED driver to regulate.
- **Sample averaging is on-chip and is decimated:** if SMP_AVE = 0b100 (16 samples), the FIFO fills at SR/16 sps. The 0b101–0b111 codes all map to 32. [Table 3, p. 18]
- **PPG_RDY in FIFO mode** asserts every sample by default. For HR with 100 Hz SR / no averaging, that's 100 INT pulses/s — too noisy. Use A_FULL with FIFO_A_FULL = ~16 unread samples for sane interrupt cadence.
- **PWR_RDY cannot be masked.** Any brown-out gives a guaranteed boot interrupt. Always clear at init.
- **HR mode (MODE=010) uses Red only by default**, but per [p. 24] *"The user can select either the Red, IR, or Green LED channel for heart rate."* — this is done via SMP_AVE / mode configuration. Practically, MODE=010 + LED2_PA != 0 is undefined — for IR-only HR, use Multi-LED with only IR slot active.
- **"Continuous time sigma-delta ADC", 18-bit, 10.24 MHz sample clock** [p. 11]. The output decimates this to the configured SR.
- **Soldering paste**: low-residue, no-clean, IR reflow only, T_solder ≤ 260 °C [p. 2, 29]. Note that the *package* surface (cover glass) should not see flux residue.
- **STAT pin / N.C. pins** can be floated or PCB-tied for mechanical stability — no electrical function [p. 9].

| WARN-07 | INT pin needs 4.7 kΩ pull-up; voltage independent of V_DDIO | LOW | [p. 30]. Driver can pull up to a different rail than VDDIO (per datasheet, up to +5 V). On Mk I pull /INT to ESP's 3V3 with 4.7 kΩ. |

| WARN-09 | Modes 000, 001, 100–110 are "do not use" | LOW | [p. 19]. Bad init logic that ORs bits into MODE could end up writing a reserved value. Recommend a single explicit constant per mode rather than bit-OR. |
| WARN-10 | Green-LED dominant-wavelength shifts with current | LOW | [p. 8 toc17]. Wavelength can shift several nm across the 0–200 mA range. Not critical for our use (HR / PPG signal is broadband relative to the LED FWHM = 35 nm) but worth knowing. |

## Open questions

1. **Re-spin v7.2 power rails for MAX30101.** Two board changes needed (1.8 V LDO for V_DD, 5 V boost rail for V_LED+). Cannot be fixed in firmware. **Action:** Ivan / hardware decides whether to delay fab for v7.2 → v7.3 or risk damage at first power-up.
2. **MAX30101 INT pull-up — to 3V3 or to V_LED+?** Datasheet allows up to +5 V. If pulled to V_LED+ (5 V boost), the ESP input will see a 5 V signal — needs level translation. Recommend: pull /INT to ESP's 3V3 (VDDIO) with 4.7 kΩ. **Action:** confirm v7.2 schematic.
3. **LED current calibration / auto-tuning.** Datasheet warns of large part-to-part variance in PA-vs-mA mapping [p. 20]. Production calibration step? Recommend: factory-calibrate at PA=0x3F during EOL test, store offset in NVS. Defer to v1.
4. **PWR_RDY-driven recovery.** When PWR_RDY fires (brown-out recovery), should the FW re-run full init or just clear the bit? Recommend: full re-init — the chip's registers are at POR and our config is lost.
5. **Die-temperature use.** v7.2 has TMP117 for skin temp. MAX30101's die-temp is meant for *SpO2 wavelength compensation* [p. 24]. Question: do we wire it up for SpO2 compensation only, or expose to fusion layer? Recommend: SpO2 only; not a user-visible signal.
6. **Sample averaging vs FIFO size.** If SMP_AVE = 0b100 (16 averages) and SR = 100 Hz, effective FIFO fill is 6.25 Hz, so 32 samples = 5.1 s of data. A_FULL at FIFO_A_FULL = 0xF (17 unread) means INT every 2.7 s. Confirm this matches the sleep-mode FIFO drain cadence target.
