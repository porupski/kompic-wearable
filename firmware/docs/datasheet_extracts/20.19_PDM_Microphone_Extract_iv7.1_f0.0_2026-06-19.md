## Interface / Protocol

**PDM confirmed — not I2S.** The MSM261DGT003 outputs a 1-bit pulse-density-modulated bitstream using a fourth-order Sigma-Delta (Σ-Δ) modulator. There are no I2S frame-sync (WS/LRCK) or I2S word-clock signals. The only two signal lines are:

- **CLK** — a clock input driven by the host (ESP32). The mic samples and modulates audio continuously at this clock rate.
- **DATA** — a 1-bit open-drain-like PDM output line. The bit density encodes instantaneous amplitude: higher density of 1s = higher sound pressure. Polarity: increasing sound = increasing density of 1s. [p. 3]

**Data format: ½ Cycle PDM.** The DATA line is driven for only one half of each clock cycle (the active half), and goes to High-Z for the other half. This allows two PDM microphones to share a single DATA line (stereo configuration) — one mic drives during the high half, the other during the low half. [p. 3, p. 7]

**L/R pin controls which half-cycle is active:**

| L/R pin | Mic name | Asserts DATA on | Latches DATA on |
|---|---|---|---|
| VDD | Mic(High) | CLK rising edge | CLK falling edge |
| GND | Mic(Low) | CLK falling edge | CLK rising edge |

**Kompic uses L/R = GND (JP9 default)** → Mic(Low) → DATA is asserted on CLK falling edge and the valid data bit is latched (read by host) on the CLK rising edge. [p. 7]

**How ESP32-S3 I2S-PDM-RX mode handles this:**
The ESP32-S3 I2S peripheral has a dedicated PDM RX mode (`I2S_COMM_FORMAT_STAND_PCM_SHORT` with PDM RX enabled via `i2s_pdm_rx_config_t`). In this mode:
- The I2S peripheral generates the CLK output on Mic_CLK (GPIO47) — there is no separate WS line.
- DATA is received on Mic_Dout (GPIO48).
- The peripheral integrates a decimation filter (CIC + IIR) that converts the incoming 1-bit PDM bitstream at the CLK frequency into multi-bit PCM samples at the target audio sample rate.
- The decimation ratio is: **decimation = f_CLK / (f_sample × 2)**. At f_CLK = 3.072 MHz and f_sample = 48 kHz, decimation = 32.
- For L/R = GND (Mic(Low)), the ESP32 PDM RX mode samples on the rising edge, which is correct.
- No MCLK or WS signals are needed or generated in PDM mode.

**Sample rate derivation (Standard Performance Mode, f_CLK = 1.1–4.0 MHz):**

The PDM bitstream must be decimated by the host to recover PCM audio. The decimation ratio determines the audio sample rate. The ESP32-S3 I2S-PDM-RX hardware decimation filter typically supports a fixed oversampling ratio of 64×.

| Target sample rate | Required f_CLK (at 64× decimation) | In-range? |
|---|---|---|
| 16 kHz | 64 × 16,000 = 1.024 MHz | Borderline — below 1.1 MHz min for Standard mode; would fall in gap between Low-Power max (900 kHz) and Standard min (1.1 MHz). **Not cleanly achievable.** |
| 44.1 kHz | 64 × 44,100 = 2.8224 MHz | Within Standard mode range (1.1–4.0 MHz). Achievable. |
| 48 kHz | 64 × 48,000 = 3.072 MHz | Within Standard mode range (1.1–4.0 MHz). Achievable. Preferred target. |

Note: the ESP32-S3 PDM RX decimation ratio is configurable (the `dn_sample_mode` field in `i2s_pdm_rx_config_t` can select ×64 or ×128 downsampling). At ×64 and f_CLK = 3.072 MHz, audio output = 48 kHz. The datasheet test condition uses f_CLK = 2.4 MHz (yielding 37.5 kHz equivalent decimated rate at 64×), which is non-standard audio — the 2.4 MHz figure is a characterisation convenience, not a recommended operating point. For Kompic, **f_CLK = 3.072 MHz → 48 kHz PCM** is the target.

For 16 kHz: use ×128 decimation at f_CLK = 2.048 MHz (within Standard mode range) → 16 kHz output. Alternatively, decimate 48 kHz PCM in firmware to 16 kHz.

## ESP32-S3 I2S-PDM configuration notes

### Driver configuration (ESP-IDF I2S PDM RX)

```c
i2s_chan_config_t chan_cfg = I2S_CHANNEL_DEFAULT_CONFIG(I2S_NUM_0, I2S_ROLE_MASTER);
i2s_new_channel(&chan_cfg, NULL, &rx_handle);

i2s_pdm_rx_config_t pdm_rx_cfg = {
    .clk_cfg = {
        .sample_rate_hz = 48000,
        .clk_src         = I2S_CLK_SRC_DEFAULT,
        .mclk_multiple   = I2S_MCLK_MULTIPLE_256,  // not used in PDM RX
        .dn_sample_mode  = I2S_PDM_DSR_8S,          // x64 decimation
    },
    .slot_cfg = I2S_PDM_RX_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_16BIT,
                                                I2S_SLOT_MODE_MONO),
    .gpio_cfg = {
        .clk  = GPIO_NUM_47,    // Mic_CLK
        .din  = GPIO_NUM_48,    // Mic_Dout
        .invert_flags = {
            .clk_inv = false,
        },
    },
};
i2s_channel_init_pdm_rx_mode(rx_handle, &pdm_rx_cfg);
```

### CLK frequency calculation

The ESP32-S3 I2S PDM RX clock is derived from the APB or PLL clock and divided down. The CLK output frequency on GPIO47 equals:

**f_CLK = sample_rate × decimation_ratio**

| sample_rate_hz | dn_sample_mode | decimation | f_CLK on GPIO47 | In mic Standard mode range? |
|---|---|---|---|---|
| 48,000 | I2S_PDM_DSR_8S (×64) | 64 | 3.072 MHz | Yes (1.1–4.0 MHz) |
| 16,000 | I2S_PDM_DSR_8S (×64) | 64 | 1.024 MHz | No — below 1.1 MHz min |
| 16,000 | I2S_PDM_DSR_16S (×128) | 128 | 2.048 MHz | Yes (1.1–4.0 MHz) |
| 44,100 | I2S_PDM_DSR_8S (×64) | 64 | 2.8224 MHz | Yes |

**Recommended operating point for Kompic:** 48 kHz, ×64 decimation, f_CLK = 3.072 MHz.

**For 16 kHz capture:** use ×128 decimation (I2S_PDM_DSR_16S) with sample_rate_hz = 16,000 → f_CLK = 2.048 MHz. Do not try 16 kHz with ×64 (f_CLK = 1.024 MHz falls in the dead band between Low-Power max 900 kHz and Standard min 1.1 MHz).

### L/R pin setting for single channel

JP9 is soldered to GND by default → L/R = GND → **Mic(Low)** mode:
- DATA is asserted on the **CLK falling edge**
- The host latches DATA on the **CLK rising edge**

ESP32-S3 PDM RX in `I2S_SLOT_MODE_MONO` with default slot configuration reads the left channel (CLK-falling-edge data), which is exactly what Mic(Low)/L=GND provides. No inversion flags needed.

If a second mic were added (stereo), it would tie L/R to VDD (Mic(High)), share the DATA line, and assert on the rising edge — the two mics share one wire without contention because each drives only during its own half-cycle.

### Decoupling

Place 100 nF ceramic + 10 µF ceramic on VDD as close to PIN 1 as possible. [p. 12] The 1.8V rail is a low-noise LDO output (XC6206) which helps, but the decoupling is still required. The PSRR of 50 dBV/FS at 1 kHz means a 200 mVpp ripple on VDD injects a −50 dBFS signal into the audio — keep the 1.8V rail clean.

### Sleep strategy

To put the mic to sleep without removing power: reduce f_CLK to ≤ 50 kHz (or stop the CLK entirely — 0 Hz is within the sleep range). The mic enters sleep in ≤ 30 µs, drawing 1 µA. Wake by restoring f_CLK ≥ 151 kHz; allow ≤ 200 µs before valid data.

In ESP-IDF: `i2s_channel_disable(rx_handle)` stops the CLK. Re-enable with `i2s_channel_enable(rx_handle)` and discard the first ~200 µs of samples.

| W1 | CLK voltage domain mismatch | MEDIUM | GPIO47 is in the "3.3V domain on R8" (iv7.1 system instructions). The mic VDD = 1.8 V, so CLK VIH max is 3.6 V absolute. ## Open questions

1. **CLK level translator needed?** The CLK line (GPIO47) is in the 3.3V domain. The mic is a 1.8V device with VIH max equal to the absolute maximum supply of 3.6V (effectively). Is there a series resistor on R8 that already limits the CLK drive voltage, or is the GPIO swinging full 3.3V to the mic CLK pin? Check the schematic: if R8 is a series resistor on the clock line forming a divider with the mic's input impedance, the voltage at the CLK pin may be safe. If R8 is a pull-up resistor (to 3.3V) on the DATA line only, the CLK drive issue remains unmitigated.

2. **Operating temperature range?** The datasheet does not specify a minimum/maximum operating temperature. For a wrist-worn device (skin contact ~20–37°C ambient, but potential exposure to −10°C to +50°C outdoors), is there any guidance from MEMSensing? Not stated in the datasheet. Assume safe based on reliability qualification range.

3. **Frequency response −3 dB lower limit?** The graph (p. 7) shows rolloff below 200 Hz but the exact −3 dB low-frequency cutoff is not tabulated. For voice/keyword detection at 300 Hz+, this is fine. For full-bandwidth audio logging down to 20 Hz, the low-frequency rolloff may clip bass content. Characterise on bring-up with a known SPL source.

4. **Does the ESP-IDF I2S PDM RX driver correctly handle Mic(Low) (L/R=GND) without clock inversion?** The ESP32-S3 Technical Reference Manual should be cross-checked to confirm that the default PDM RX configuration reads DATA on the rising CLK edge, matching Mic(Low) behaviour. If the driver defaults to Mic(High) (rising-edge assertion), set `clk_inv = true` in `invert_flags`.

5. **Actual sensitivity in dBV/Pa?** The datasheet expresses sensitivity in dBFS (relative to digital full-scale), not dBV/Pa. Converting to dBV/Pa requires knowing the ADC reference, which is internal to the Σ-Δ modulator and not stated. For absolute SPL calibration, characterise against a known source on the bench. The ±1 dB sensitivity matching is useful for stereo applications but Kompic uses only one mic.

6. **R8 role clarification:** iv7.1 mentions "3.3V domain on R8" for both GPIO47 and GPIO48. Is R8 a single series resistor on the CLK line, a pull-up on DATA, or something else? This directly affects W1 above.
