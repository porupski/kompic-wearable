### Transaction format (I²C)

**Write:**
```
S · 0xD6 (W) · A · sub_addr · A · DATA · ... · A · P
```
With IF_INC = 1 (default), `sub_addr` auto-increments for each subsequent DATA byte.

**Read:**
```
S · 0xD6 (W) · A · sub_addr · A · SR · 0xD7 (R) · A · DATA · A · DATA · ... · NA · P
```

**Critical:** unlike LIS3MDL [20.07] which uses bit 7 of sub-address to enable auto-increment, **LSM6DSV16X uses the IF_INC bit in CTRL3 — global, default ON**. Don't OR `0x80` into sub-addresses (would create an invalid address that wraps).

### CTRL1 (0x10) — Accelerometer power mode + ODR [p. 65 §9.14]

```
[7]      reserved  must be 0
[6:4]    OP_MODE_XL[2:0]    Operating mode:
                              000 = High-Performance (default)
                              001 = High-Accuracy ODR (HAODR)
                              010 = reserved
                              011 = ODR-triggered (external sync via INT2)
                              100 = Low-Power mode 1 (2-mean average)
                              101 = Low-Power mode 2 (4-mean)
                              110 = Low-Power mode 3 (8-mean)
                              111 = Normal mode
[3:0]    ODR_XL[3:0]         ODR selection:
                              0000 = Power-down (default)
                              0001 = 1.875 Hz (LP only)
                              0010 = 7.5 Hz · 0011 = 15 · 0100 = 30 · 0101 = 60
                              0110 = 120 · 0111 = 240 · 1000 = 480 · 1001 = 960
                              1010 = 1.92 kHz · 1011 = 3.84 kHz · 1100 = 7.68 kHz
```

**Default = `0x00`** → accel power-down, ODR = 0. FW must explicitly enable.

### CTRL2 (0x11) — Gyroscope power mode + ODR [p. 66 §9.15]

```
[7]      reserved  must be 0
[6:4]    OP_MODE_G[2:0]      Operating mode:
                              000 = High-Performance (default)
                              001 = High-Accuracy ODR (HAODR)
                              010 = reserved
                              011 = ODR-triggered
                              100 = Sleep mode (gyro paused but warm — fast wake)
                              101 = Low-Power mode
                              110-111 = reserved
[3:0]    ODR_G[3:0]          ODR selection:
                              0000 = Power-down (default)
                              0010 = 7.5 Hz (LP/HP) · 0011 = 15 · 0100 = 30 · 0101 = 60
                              0110 = 120 · 0111 = 240 · 1000 = 480 · 1001 = 960
                              1010 = 1.92 kHz · 1011 = 3.84 kHz · 1100 = 7.68 kHz
```

**Default = `0x00`** → gyro power-down, ODR = 0.

**Gyro sleep mode** is a powerful feature: keeps the gyro **warm** so wake takes <1 ms instead of the cold turn-on time (T_on = 30 ms typ) [p. 14 Table 4]. Trade-off: sleep mode still consumes more than full power-down.

### CTRL3 (0x12) — Boot / Block-data-update / Reset [p. 67 §9.16]

```
[7]   BOOT       1 = reload memory content from internal Flash (auto-clears)
[6]   BDU        1 = output regs not updated until both bytes read (default 1) — RECOMMENDED
[2]   IF_INC     1 = sub-address auto-increment in multi-byte access (default 1)
[0]   SW_RESET   1 = software reset of all control regs (auto-clears)
```

**Default = `0x44`** = `0100 0100` → BDU=1 (good), IF_INC=1 (good).

### INT1_CTRL (0x0D) — INT1 source enables [p. 63 §9.11]

```
[6]   INT1_CNT_BDR     COUNTER_BDR_IA → INT1
[5]   INT1_FIFO_FULL   FIFO full → INT1
[4]   INT1_FIFO_OVR    FIFO overrun → INT1
[3]   INT1_FIFO_TH     FIFO threshold (watermark) → INT1
[1]   INT1_DRDY_G      Gyro data-ready → INT1
[0]   INT1_DRDY_XL     Accel data-ready → INT1
```

**INT1 output is the OR of selected sources here AND in MD1_CFG (0x5E)** — the latter handles wake-up, free-fall, tap, 6D, activity/inactivity routing. INT2_CTRL (0x0E) is the mirror for INT2.

### Embedded functions interrupts (MD1_CFG at 0x5E)

Lives in the primary register space (no bank switch needed). Routes wake-up, sleep, free-fall, double-tap, single-tap, 6D, etc. to INT1. Covered in companion **20.10b** for the FSM/MLC details — but for v7.2 **wrist-raise-to-wake** style detection, MD1_CFG.INT1_WU = 1 is the relevant bit.

## Initialization sequence (basic accel+gyro+INT1 wake-on-motion)

```
1. (HW) +3.2 V applied to V_DD and V_DD_IO. CS pin tied to V_DD_IO. SDO/SA0 tied to V_DD_IO.
   Wait 10 ms for chip POR (datasheet implicit; conservative).
2. Verify presence:
     i2c_write(0x6B, 0x0F);  i2c_read(1) → expect 0x70
3. Software reset for clean state:
     i2c_write(0x6B, 0x12, 0x01);     // CTRL3.SW_RESET = 1
     poll CTRL3 until SW_RESET reads 0 (~5 ms)
4. Wait for BOOT to complete:
     i2c_write(0x6B, 0x12, 0x80);     // CTRL3.BOOT = 1
     wait 10 ms (datasheet silent on exact boot time; conservative)
5. (Optional) Configure INT pin behavior:
     i2c_write(0x6B, 0x03, 0x00);     // IF_CFG = default: active-HIGH push-pull
     (or 0x10 for active-LOW push-pull)
6. Configure accel:
     i2c_write(0x6B, 0x17, 0x01);     // CTRL8 = ±4g (FS_XL = 01)
     i2c_write(0x6B, 0x10, 0x05);     // CTRL1 = HP mode (000), 60 Hz (0101)
     → Accel now running at 60 Hz, ±4 g, HP mode (~190 µA)
7. Configure gyro:
     i2c_write(0x6B, 0x15, 0x04);     // CTRL6 = ±2000 dps (FS_G = 0100)
     i2c_write(0x6B, 0x11, 0x55);     // CTRL2 = LP mode (101), 60 Hz (0101)
     → Gyro now running at 60 Hz, ±2000 dps, LP mode
     Wait T_on = 30 ms for gyro to stabilize
8. (Optional, recommended) Confirm BDU + IF_INC:
     i2c_write(0x6B, 0x12, 0x44);     // CTRL3 = BDU=1, IF_INC=1
9. (Optional) Enable INT1 on accel data-ready:
     i2c_write(0x6B, 0x0D, 0x01);     // INT1_CTRL.INT1_DRDY_XL = 1
10. (Optional, for wake-on-motion) See 20.10b for wake-up / activity-detection setup.
11. Steady-state: read 12 bytes from 0x22 (gyro X_L) through 0x2D (accel Z_H) in one burst.
```

## Operation

### Reading IMU samples (canonical 12-byte burst)

```
S · 0xD6 (W) · A · 0x22 · A · SR · 0xD7 (R) · A ·
  G_X_L · A · G_X_H · A · G_Y_L · A · G_Y_H · A · G_Z_L · A · G_Z_H · A ·
  A_X_L · A · A_X_H · A · A_Y_L · A · A_Y_H · A · A_Z_L · A · A_Z_H · NA · P

gyro_x_dps = (int16_t)((G_X_H << 8) | G_X_L) × G_So[FS]
accel_x_g  = (int16_t)((A_X_H << 8) | A_X_L) × LA_So[FS] / 1000.0
```

With BDU=1, byte pairs are atomic — no tearing when ODR > read rate.

### Operating mode strategy (wearable)

| Mode | OP_MODE_XL | OP_MODE_G | Avg current (60 Hz) | Use case |
|---|---|---|---|---|
| **Both PD** | n/a (ODR=0) | n/a (ODR=0) | **2.6 µA** | Truly off (no motion detection) |
| Wake-on-motion | LP mode 1, ODR 30 Hz | PD | **~10 µA** | Sleep watching for wrist raise — most common |
| Active tracking (low-power) | LP mode 2, ODR 60 Hz | PD | **~22 µA** | Pedometer / step count |
| Combo HP | HP, 60 Hz | HP or sleep | **190 + 650 µA = ~840 µA** | Gesture, 6D orientation, full sensor fusion |
| Maximum perf | HP, 1.92 kHz | HP, 1.92 kHz | ~1.5 mA | High-bandwidth motion capture (rare for wearable) |

**Wearable recommendation:** **accel LP mode 1 @ 30 Hz, gyro power-down** for screen-off background → ~10 µA. Switch to **HP combo @ 60–120 Hz** when display turns on. Negligible vs. display + radio loads.

| **INT1** | 4 | **Active HIGH** (IF_CFG.H_LACTIVE = 0) | Push-pull (IF_CFG.PP_OD = 0) | DRDY_XL, DRDY_G, FIFO TH/OVR/FULL, CNT_BDR (INT1_CTRL) + wake, free-fall, tap, 6D, activity, FSM/MLC (MD1_CFG) |
| INT2 | 9 | Active HIGH (same H_LACTIVE bit) | Push-pull (same PP_OD bit) | Same set as INT1 (INT2_CTRL + MD2_CFG) — plus DRDY_G_EIS, EMB_FUNC_ENDOP, DRDY_TEMP, DRDY_AH_QVAR |

**Both INT pins share polarity / drive-type via IF_CFG** — can't have INT1 push-pull and INT2 open-drain. v7.2 likely uses defaults (active-high push-pull) since GPIO8 "raise-to-wake" implies a rising-edge wake.

**INT1 source = OR of (INT1_CTRL bits) OR (MD1_CFG bits)** — both register groups feed the same physical pin.

**Clear mechanism:**
- DRDY sources: read of relevant data register clears the flag (with DRDY_PULSED = 0)
- Pulsed mode (CTRL4.DRDY_PULSED = 1): INT1 pulses for ~65 µs per new sample — no clear needed
- Wake/tap/activity/free-fall events: read the relevant SRC register (e.g., WAKE_UP_SRC at 0x45) to clear

## Datasheet notes

- **Triple-channel architecture** [p. 3 §1]: UI (Channel 1, main host interface), EIS (Channel 3, dedicated gyro for image stabilization), OIS (Channel 2, aux SPI for camera modules). **v7.2 uses only Channel 1 (UI)** — EIS/OIS channels are leftover capability for smartphone OEMs.
- **Triple-mode pin configuration** [p. 10 Fig. 6]: Mode 1 = host-only, Mode 2 = + I²C master for sensor hub, Mode 3 = + aux SPI for camera. v7.2 = **Mode 1**.
- **Dual-channel accelerometer** [p. 32 §6.3, p. 71 CTRL8]: if enabled (XL_DualC_EN=1), one ADC produces two outputs: Ch1 with user-selectable FS, Ch2 fixed at ±16 g. Useful for tap detection (high FS) + general motion (lower FS) simultaneously. Not needed for v7.2 baseline.
- **High-Accuracy ODR mode (HAODR)** [p. 33 §6.5]: improves ODR precision over temp/supply variation; +20 µA cost. For wearable, not needed.
- **ODR-triggered mode** [p. 34 §6.6]: external sync via INT2 pin. Use case = host-locked sample timing (camera frame sync). Not needed for v7.2.
- **CTRL3 default = 0x44** — BDU=1 and IF_INC=1 already set. No FW action needed unless you want to disable them.
- **WHO_AM_I = 0x70** — unique across STM IMU family. Don't confuse with LSM6DSO (0x6C), LSM6DSV (0x70 — *same as DSV16X*), LSM6DSV16B (0x71). Validate part marking matches BOM.
- **MIPI I3C support** [p. 27 §5.2] — backward-compatible I²C address 0x6B until dynamic address is assigned. Anti-spike filter ASF_CTRL needs setting if host stays in I²C mode at high speed [p. 29 §5.2.3]. v7.2 stays in I²C — set ASF_CTRL=1 if encountering bus glitches.
- **Sensor Fusion Low-Power (SFLP)** [p. 8 §2.8]: on-chip Game Rotation Vector quaternion, gravity vector, gyro bias — 0.7° static heading, 0.5° pitch/roll at low dynamic. Saves running Madgwick/Mahony on the ESP. Covered in 20.10b.
- **Embedded pedometer at 30 Hz, independent of selected ODR** [p. 4 §2.1] — runs in its own ultralow-power domain. Detail in 20.10b.
- **Smart FIFO compression** [p. 4 §2]: 2× or 3× compression depending on data variability. Effective depth up to ~13 KB.
- **OIS chain disable** for ±4000 dps gyro [p. 69 CTRL6 footnote] — if FS_G = 1100, must clear OIS_G_EN bit. Not relevant for v7.2 (we won't use ±4000 dps).
- **Datasheet Rev. 4 (May 2023)** — current.

## Warnings & Errata

| ID | Title | Source | Severity | Description / Mitigation |
|---|---|---|---|---|
| WARN-01 | **Default INT polarity is active HIGH, push-pull** | [p. 58 §9.3 IF_CFG] | **MED** | Different from many ST sensors (LIS3MDL default active LOW). If FW expects active-low ISR, it'll never fire. **Mitigation:** explicitly set IF_CFG in init: 0x00 for active-HIGH (matches v7.2 "raise-to-wake"); 0x10 for active-LOW. ESP-S3 GPIO8 wake-edge config must match. |
| WARN-02 | **Pins 2, 3 (SDx/AH/Qvar) must be tied to defined level** | [p. 11 Table 2] | **MED** | "Connect to V_DD_IO or GND if the analog hub and Qvar are disabled." Floating these pins is undefined. **Mitigation:** v7.2 schematic must tie both to GND (or both to V_DD_IO, but GND is simpler). Confirm. |
| WARN-03 | **CS pin must be tied HIGH for I²C mode** | [p. 11 Table 2] | **MED** | If CS floats or is grounded, the chip enters SPI mode and the I²C interface is disabled. **Mitigation:** v7.2 schematic must tie CS (pin 12) to V_DD_IO. Confirm. |
| WARN-04 | **Both sensors boot in POWER-DOWN** | [p. 65 §9.14; p. 66 §9.15] | **HIGH** | After POR, CTRL1 = CTRL2 = 0x00 → both sensors off. FW must write at least CTRL1 to start sampling. Forgetting = "IMU returns zeros" bug. **Mitigation:** init sequence step 6/7 is mandatory. |
| WARN-05 | **Gyro turn-on T_on = 30 ms** | [p. 14 Table 4] | MED | After power-up or wake from PD, the gyro takes 30 ms before output is valid. FW must mask or discard early gyro samples. Sleep mode (OP_MODE_G = 100) keeps the gyro warm to skip this. **Mitigation:** after writing CTRL2 to enable gyro, wait ≥30 ms before reading. Or use sleep mode and accept the elevated idle current. |
| WARN-06 | **Multi-byte auto-increment is global (CTRL3.IF_INC), not per-transaction** | [p. 67 §9.16] | MED | Unlike LIS3MDL where bit 7 of sub-address enables auto-increment per access, LSM6DSV16X uses a global IF_INC bit (default 1). If FW disables IF_INC for one transaction, **it stays off** for subsequent transactions until re-enabled. **Mitigation:** leave IF_INC=1 always (default). Don't touch CTRL3 bit 2 unless absolutely needed. |
| WARN-07 | **WHO_AM_I = 0x70 is shared with LSM6DSV** | [p. 64 §9.13] | MED | The base LSM6DSV (no -16X suffix) also returns 0x70. WHO_AM_I alone cannot distinguish LSM6DSV16X from LSM6DSV. To confirm 16X (with Qvar/SFLP/MLC capability), check that embedded function registers respond. **Mitigation:** BOM trace must confirm part marking. If runtime distinction is needed, attempt to read EMB_FUNC_EN_A or similar 16X-specific register. |
| WARN-08 | **Bank switching required for embedded functions** | [p. 56 §9.1] | MED | MLC, FSM, sensor hub registers live in separate banks — must set FUNC_CFG_ACCESS.EMB_FUNC_REG_ACCESS = 1 (or SHUB_REG_ACCESS = 1) before accessing. **Forget to switch back** → you've been writing into the wrong bank. **Mitigation:** wrap embedded-function configuration in `bank_switch(EMBED) → write... → bank_switch(MAIN)`. See 20.10b. |
| WARN-09 | **±4000 dps gyro requires OIS chain disabled** | [p. 69 CTRL6 footnote 1] | LOW | FS_G = 1100 (±4000 dps) requires OIS_G_EN = 0 in UI_CTRL1_OIS (0x70). Not a v7.2 concern (we don't use ±4000 dps), but note for future high-rotation use cases. |
| WARN-10 | **MIPI I3C anti-spike filter setting affects high-speed reliability** | [p. 29 §5.2.3] | LOW | If staying in I²C mode at 400 kHz with anti-spike filter managed by protocol (ASF_CTRL=0), the filter may be turned off after broadcast. **Mitigation:** if encountering occasional I²C corruption, set ASF_CTRL=1 in IF_CFG to keep the filter always on. |
| WARN-11 | **SHARED BDU on accel + gyro** | [p. 67 CTRL3.BDU] | LOW | BDU=1 protects both accel and gyro registers together. There's no per-sensor BDU. Reading accel locks gyro too until both LSB/MSB are consumed — usually fine, but worth knowing if doing partial reads. |
| WARN-12 | **OUT_TEMP offset is 0 LSB at 25 °C** | [p. 15 §4.3 footnote 3] | LOW | Temperature register zero is at 25 °C, not 0 °C. Conversion: T_°C = TEMP / 256 + 25. Easy to misread if treating the value as 256 LSB/°C from 0 °C. |

## Open questions

- **Q1 — INT2 pin routing.** Currently unrouted in v7.2 (assumed). Useful for separating event types (e.g., INT1 = wake gesture, INT2 = DRDY for pulled sampling). Not blocking. **Action:** consider for v7.3.
- **Q2 — Self-test in production.** Run accel + gyro self-test at every cold boot to detect dead silicon? Cost ~200 ms. **Action:** FW policy decision.
- **Q3 — SFLP (Sensor Fusion Low-Power) vs host-side fusion.** SFLP gives game rotation vector quaternion on-chip. Saves ESP CPU. Trade-off: harder to tune algorithm parameters. **Action:** decide based on FW maturity target. See 20.10b for SFLP setup.
- **Q4 — Wake-on-motion thresholds.** Default wake threshold is conservative; for wrist-raise gesture, may need tuning (e.g., 30 mg threshold, 2 samples persistence). **Action:** bench-tune on assembled watch.
- **Q5 — Use of CTRL4.DRDY_MASK?** Useful if applying high-pass filter — masks DRDY until filter settles. Default 0 means DRDY fires on every new sample regardless. **Action:** enable if FW uses HP path for tap/gesture.
- **Q6 — Pedometer enable.** Cheap and useful for wearable. Independent ODR (30 Hz), runs in ultralow-power domain. **Action:** enable by default — see 20.10b for embedded function setup.
