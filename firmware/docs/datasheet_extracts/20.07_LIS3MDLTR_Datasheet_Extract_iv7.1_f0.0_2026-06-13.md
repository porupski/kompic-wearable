### Read protocol [p. 12 Table 13–14]

**Single byte read:**
```
S · 0x38 (W) · SAK · reg_addr · SAK · SR · 0x39 (R) · SAK · DATA · NMAK · P
```

**Multi-byte read (e.g., 6 bytes from OUT_X_L = 0x28):**
```
S · 0x38 (W) · SAK · 0xA8 (= 0x80 | 0x28) · SAK · SR · 0x39 (R) · SAK ·
  OUT_X_L · MAK · OUT_X_H · MAK · OUT_Y_L · MAK ·
  OUT_Y_Y · MAK · OUT_Z_L · MAK · OUT_Z_H · NMAK · P
```

**Critical:** without the `0x80` OR on the register address, only one byte is read regardless of how many you clock. This is a non-standard auto-increment scheme (different from most STM sensors and from the VEML6030 cmd-based scheme). See WARN-05.

### CTRL_REG1 (0x20) bit fields [p. 20 Tables 17, 18]

```
[7]    TEMP_EN     — 0=off, 1=on (TEMP_OUT registers active)
[6:5]  OM[1:0]     — X/Y operating mode:
                       00 = Low-power (LP)
                       01 = Medium-performance (MP)
                       10 = High-performance (HP)
                       11 = Ultrahigh-performance (UHP) ← lowest noise, ~270 µA
[4:2]  DO[2:0]     — Output Data Rate:
                       000=0.625 Hz, 001=1.25, 010=2.5, 011=5,
                       100=10 (default), 101=20, 110=40, 111=80
[1]    FAST_ODR    — 0=use DO[2:0]; 1=use mode-specific high rates:
                       LP→1000 Hz · MP→560 · HP→300 · UHP→155
[0]    ST          — Self-test enable (0=off, 1=on)
```

### CTRL_REG2 (0x21) bit fields [p. 21 Tables 22–24]

```
[6:5]  FS[1:0]     — Full scale:  00=±4g · 01=±8g · 10=±12g · 11=±16g
[3]    REBOOT      — 1 = reload factory cal from internal NVM (does NOT clear user regs)
[2]    SOFT_RST    — 1 = reset all configuration registers to default (clears CTRL/INT regs)
                     bits [7], [4], [1], [0] must remain 0
```

### CTRL_REG3 (0x22) bit fields [p. 21 Tables 25–27]

```
[5]    LP          — 1 = low-power: forces ODR=0.625 Hz, minimum averaging (~few µA)
                     0 = normal (use DO[2:0] from CTRL_REG1)
[2]    SIM         — 1 = SPI 3-wire (ignored in I²C)
[1:0]  MD[1:0]     — System operating mode:
                       00 = Continuous-conversion
                       01 = Single-conversion (one-shot)
                       10 / 11 = Power-down ← DEFAULT (0x03)
```

**Default 0x03 = power-down** — the device boots OFF. FW must write MD[1:0]=00 (continuous) or 01 (single) to start sampling. See WARN-06.

### CTRL_REG4 (0x23) bit fields [p. 22 Tables 28–30]

```
[3:2]  OMZ[1:0]    — Z-axis operating mode (00=LP, 01=MP, 10=HP, 11=UHP).
                     Often set same as OM[1:0] for matched noise across axes.
[1]    BLE         — 0 = LSB at lower address (default, little-endian on the wire)
                     1 = MSB at lower address (big-endian)
```

### CTRL_REG5 (0x24) bit fields [p. 22 Tables 31–32]

```
[7]    FAST_READ   — 1 = OUT_x_L registers not updated; only high byte changes
                       (saves bus time when only 8-bit resolution is needed)
[6]    BDU         — 1 = output regs held static between LSB and MSB reads (recommended)
                     0 = continuous update (risk of tearing across high/low byte boundary)
```

**Strongly recommend BDU = 1** in firmware to avoid 16-bit tearing when sampling rate ≈ read rate.

### STATUS_REG (0x27) [p. 23 Tables 33–34]

```
[7]  ZYXOR  — overrun on any axis (data lost)
[6]  ZOR    — overrun on Z
[5]  YOR    — overrun on Y
[4]  XOR    — overrun on X
[3]  ZYXDA  — new data available on all 3 axes (use this for "data fresh" check)
[2]  ZDA    — Z fresh

### INT_CFG (0x30) bit fields [p. 24 Tables 35–36]

```
[7]  XIEN  — 1 = enable threshold INT on X axis (default 1)

## Initialization sequence

[Synthesized from §5, §7.5–7.9, §4.1]

```
1. (HW) +3.2 V (Vdd) and Vdd_IO power up; CS = Vdd_IO; SA1 = GND.
   Mandatory caps: C1=100nF (pin 4), C2=1µF + C3=100nF (Vdd).
2. (Optional) Verify presence: read 0x0F → expect 0x3D.
3. (Optional but recommended) Soft reset:
     Write CTRL_REG2 (0x21) = 0x04   (SOFT_RST=1)
     Wait ~5 ms (datasheet silent on exact reset time — be generous)
4. Configure full-scale:
     Write CTRL_REG2 (0x21) = (FS << 5)
     For ±4 g (v7.2): 0x00
5. Configure XY operating mode + ODR + temp sensor:
     Write CTRL_REG1 (0x20) = (TEMP_EN<<7) | (OM<<5) | (DO<<2) | (FAST_ODR<<1)
     For UHP + 10 Hz + temp enabled: 0x80 | (3<<5) | (4<<2) = 0xF0
     For HP + 20 Hz + temp off:  (2<<5) | (5<<2) = 0x54
6. Configure Z operating mode (match XY for matched noise):
     Write CTRL_REG4 (0x23) = (OMZ<<2)
     For UHP: 0x0C
7. Enable block data update:
     Write CTRL_REG5 (0x24) = 0x40   (BDU=1)
8. (Optional) Load hard-iron offsets from NVS:
     Write OFFSET_X_REG_L (0x05) through OFFSET_Z_REG_H (0x0A) — 6 bytes
9. Start continuous conversion:
     Write CTRL_REG3 (0x22) = 0x00   (MD=00 continuous, LP=0, SIM=0)
10. (Optional) Configure interrupt:
     a. INT_THS_L/H = threshold (15-bit unsigned, |axis| > THS triggers INT)
     b. INT_CFG = (XIEN|YIEN|ZIEN|reserved|IEA|LIR|IEN)
        For active-low, latched, all axes, INT pin enabled:
          0xE8 | 0x02 | 0x01 = 0xEB
11. Settling time:
     Datasheet silent on first-sample-after-startup time. Recommend
     wait 1/ODR + 50 ms before trusting first reading.
12. Steady-state: poll STATUS_REG.ZYXDA (or watch INT/DRDY pin),
     read 6 bytes from OUT_X_L (with 0x80 OR'd into the sub-address)
     in a single transaction.
```

**Critical timings:**
- Soft reset: datasheet silent on duration; allow 5 ms.
- First-sample latency after MD=00 write: approximately 1 ODR period for the first valid sample.
- Self-test settling: write ST=1, wait several samples for settle, validate per-axis change is within ST min/max bounds (1–3 gauss for X/Y at ±12 g, 0.1–1 gauss for Z) [p. 4 Table 2].

## Operation

### Reading magnetic data (canonical) [p. 23, p. 12]

```
S · 0x38 (W) · SAK · 0xA8 · SAK · SR · 0x39 (R) · SAK · {6 bytes} · NMAK · P

raw_X = (int16_t)((OUT_X_H << 8) | OUT_X_L)
raw_Y = (int16_t)((OUT_Y_H << 8) | OUT_Y_L)
raw_Z = (int16_t)((OUT_Z_H << 8) | OUT_Z_L)

gauss_X = raw_X / 6842.0   // at FS = ±4 g
gauss_Y = raw_Y / 6842.0
gauss_Z = raw_Z / 6842.0
```

With BDU=1, the L/H byte pair for each axis is locked the instant the low byte is read; this protects against the chip updating mid-pair.

### Polling vs interrupt

- **Polling** (recommended for v7.2 compass use):
  - Configure ODR (e.g., 10 Hz), enable continuous mode.
  - On each application loop, read STATUS_REG.ZYXDA — if 1, read 6 bytes.
  - Use DRDY pin (pin 8) if low-jitter sampling is needed (not currently routed in v7.2).
- **Interrupt** (for "magnet detected" use cases — e.g., flap-cover smart watch):
  - Set INT_THS_L/H to ~1 gauss above ambient.
  - Enable IEN, route INT to ESP-S3 GPIO with falling-edge detect.

### Hard-iron compensation [p. 19 §7.1–7.3]

The OFFSET_X/Y/Z_REG pairs hold a 16-bit two's-complement value that is **subtracted from the raw axis reading inside the chip** before it's exposed via OUT_X/Y/Z. Use this to remove the LRA magnet's DC bias and any other fixed-environment hard-iron sources:

```
1. Calibration phase (user-initiated "rotate compass" routine):
   - Sample axes through full 3-axis sphere rotation
   - Compute per-axis offset = (max + min) / 2
   - Store in ESP NVS (key: "mag_offset_x", "mag_offset_y", "mag_offset_z")

2. Boot phase (every cold boot or after RESET):
   - Read NVS values
   - Convert to two's-complement 16-bit
   - Write to OFFSET_X_REG_L (0x05) through OFFSET_Z_REG_H (0x0A) — 6 bytes
   - From this point, OUT_X/Y/Z values are hard-iron-compensated
```

**Soft-iron compensation** (3×3 matrix rotation) is **purely software** — apply it after reading the hard-iron-compensated values [WARN-10].

### Operating modes (XY noise vs current trade-off)

| Mode | OM[1:0] | RMS noise @±12 g | I_DD @ ODR=20 Hz | Best for |
|---|---|---|---|---|
| Low-power (LP) | `00` | ≈ tens of mgauss | **40 µA** | sleep-mode compass check |
| Medium-perf (MP) | `01` | intermediate | ~100 µA (interp) | balanced use |
| High-perf (HP) | `10` | intermediate-low | ~170 µA (interp) | active compass |
| **Ultra-high (UHP)** | `11` | **X/Y 3.2 mgauss · Z 4.1 mgauss** | **270 µA** | navigation-grade |

**Recommendation:** for a wearable compass, **MP @ 10 Hz** is the sweet spot — adequate noise (≈10 mgauss class, 100× smaller than Earth field) at modest power (~50–80 µA).

### Single-conversion / one-shot mode

Useful for ultra-low average power: wake → write MD=01 → wait 1 ODR period → read → MD=10/11 (power-down). At a 1 Hz duty cycle, average current ≈ I_active × T_active / T_total ≈ 270 µA × 100 ms / 1 s = **27 µA** in UHP, or **4 µA** in LP.

### Self-test [p. 4 Table 2; p. 20 ST bit]

1. Write CTRL_REG2 = `0x40` (FS = ±12 g — self-test bounds are specified at this FS).
2. Set CTRL_REG1.OM = UHP, DO = 10 Hz.
3. Capture an average baseline of 8 samples per axis.
4. Write CTRL_REG1.ST = 1.
5. Wait 60 ms (data settling).
6. Capture another 8 samples; subtract baseline.
7. Validate: X delta in [1, 3] gauss; Y in [1, 3] gauss; Z in [0.1, 1] gauss.
8. Write ST = 0 to disable; restore application FS.

### System budget recommendations

- **Background compass while watch face shown** (10 Hz, MP mode): ≈ 80 µA continuous on 3.2 V rail.
- **Idle / screen-off** (compass off, MD=power-down): ≈ 1 µA. Negligible.
- **Sport mode / navigation** (UHP, 20 Hz): 270 µA continuous — significant but acceptable for an active session. If display is on (50+ mA), the compass cost is ~0.5 % of total draw.
- **LRA-bias zeroing during heading calc**: no extra power cost — happens inside the chip via the offset registers.

## Datasheet notes

- **Factory calibration** [p. 9 §3.3]: sensitivity (So) and zero-gauss level (TyOff) are factory-trimmed and stored in NVM. **REBOOT bit (CTRL_REG2.bit3)** reloads the factory cal from NVM to active registers — useful if anything got corrupted at runtime.
- **Hard-iron offset registers (0x05–0x0A) are RAM, NOT NVM** [p. 19 §7.1] — they reset to 0 every power cycle. FW must reload from NVS each boot.
- **OUT_x register byte order**: with BLE = 0 (default), the L byte is at the lower address. Big-endian (BLE = 1) is rarely useful — leave default.
- **Magnetic disturbance field (DF)**: zero-gauss offset starts to degrade above 50 gauss [p. 4 Table 2]. LRA magnets (~1 gauss at a few mm) are well within tolerance. Avoid placing high-flux components (motors, coils > 10 gauss) near the sensor.
- **High-current wiring** [p. 10 §4.3]: "Keep currents higher than 10 mA a few millimeters away from the sensor IC." The TPS62840 SW node is the biggest offender (peaks > 1 A switching) — **route the SW trace AWAY from the LIS3MDL footprint**.
- **Temperature sensor**: 8 LSB/°C, refresh rate = ODR (when TEMP_EN=1) [p. 5 Table 3]. Useful for crude temperature compensation of the magnetometer itself, NOT as a substitute for the TMP117 skin temp [20.09].
- **Independent IO supply (V_DD_IO)** [p. 1 Features]: designed for level-shifted operation (e.g., 1.8 V IO with 3.0 V core). v7.2 ties IO = core = 3.2 V, which is allowed but slightly less efficient.
- **Datasheet revision 7 (Dec 2023)** — adds hard-iron offset registers (0x05–0x0A) which were not present in revisions ≤ 5. **Confirm the v7.2 BOM line resolves to a recent silicon batch** that includes these — *very old stockpile may behave differently*. See Open Q5.
- **Self-test bounds are specified at FS=±12 g** [p. 4 Table 2]. Self-test code must temporarily switch FS regardless of operational FS.
- **No FIFO** — readings must be consumed at the ODR or risk overrun (STATUS_REG.ZYXOR). For 10 Hz, that's 100 ms — easy.

## Open questions

- **Q1 — V_DD_IO supply choice.** v7.2 has only the 3.2 V rail available. Confirm V_DD_IO is wired directly to V_DD (same net), not floating. **Action:** schematic review.
- **Q2 — Hard-iron offset storage in NVS.** Define the NVS key schema and validation (CRC + version tag) so a corrupt or missing value triggers an in-flight re-cal prompt. **Action:** FW design.
- **Q3 — DRDY pin routing.** Pin 8 is unrouted in v7.2 (assumed — confirm). For low-jitter compass sampling, route DRDY to an ESP GPIO in v7.3. Not blocking for v0. **Action:** v7.3 board change request.
- **Q4 — Axis orientation alignment.** Confirm the chip's +Y axis points toward the watch's 12 o'clock direction on v7.2 silkscreen. If not, the firmware compass library needs a rotation. **Action:** confirm via Ivan's v7.2 mechanical placement.
- **Q5 — Silicon revision check.** OFFSET_x registers (0x05–0x0A) were added in datasheet Rev. 7 (Dec 2023). Earlier LIS3MDL chips from stockpile may behave differently. **Action:** verify date code on parts when they arrive; if pre-2024, fall back to software-only hard-iron compensation.
- **Q6 — Soft-iron calibration approach.** A 3×3 matrix is the gold standard; the simpler "ellipsoid fit" approach is good enough for non-navigation use. **Action:** pick the FW algorithm based on heading accuracy target (1° vs 5°).
- **Q7 — Self-test in production.** Run self-test at every cold boot to detect a dead-sensor or magnetically saturated sensor? Cost is ~100 ms boot delay. **Action:** FW policy decision.
- **Q8 — INT vs DRDY usage.** Polling is simplest and matches v7.2's "compass on demand" model. INT-driven compass is overkill unless we want magnet-field-event wake from deep-sleep (door-cover use case). **Action:** product decision.
