## Pinout (summary) [p. 9 Fig. 2, Table 10; p. 10 Table 11]

LCC-style module with castellated pads. 18 pads total. Top-view, two columns (1–9 right, 10–18 left). Module is **~10 × 9.7 × 2.5 mm — by far the largest chip on the wearable PCB**.

| Pin | Symbol | Type | Function | Notes |
|---|---|---|---|---|
| 1 | GND | PWR | Ground | — |
| **2** | **TXD** | OUT | **UART TX** — outputs NMEA / UBX from the module | Drives RX of host (ESP-S3 GPIO18). Input pull-up in standby. |
| **3** | **RXD** | IN | **UART RX** — receives commands from host | From TX of host (ESP-S3 GPIO17). Input pull-up. |
| **4** | **TIMEPULSE** | OUT | **1 PPS** time-pulse signal (default; configurable 0.25 Hz–10 MHz) | **Shared with SAFEBOOT_N via internal 1 kΩ** [p. 9 Table 10 footnote 15] — see WARN-05. Drive 4 mA. v7.2: GPIO46 wakes ESP from 1 PPS. |

| 7 | V_IO | PWR | IO voltage supply | 1.76–V_CC max. Selected by VIO_SEL pin. **Switch off 100 ms before V_CC** when entering hardware backup [p. 11 §4.2 warning]. |

| 10 | GND | PWR | Ground | |

**Pin states across modes** [p. 10 Table 11]:
- **Continuous mode**: TXD = output (active); RXD/SDA/SCL/EXTINT = input pull-up; TIMEPULSE = output; LNA_EN = output HIGH.
- **Software standby mode**: all PIOs = input pull-up; **LNA_EN = pull-DOWN** (turns off external active antenna automatically).
- **Safe-boot mode**: TXD active; TIMEPULSE = output LOW.
- **Reset (RESET_N = LOW)**: all PIOs = input pull-up.
- **Hardware backup mode** (V_CC = V_IO = 0): "PIOs must not be driven" [p. 10] — driving any pin high while only V_BCKP is alive can damage the module.

**Transaction direction:**
- TX from MAX-M10S → ESP-S3 RX (GPIO18): NMEA sentences + optional UBX binary responses
- RX into MAX-M10S ← ESP-S3 TX (GPIO17): NMEA $PUBX commands or UBX binary commands

**NMEA buffer overflow risk at default 9600 baud with multi-constellation:**
- GPS+Galileo+BeiDou enabled → up to ~30 satellites visible
- GSV messages alone (one per 4 sats) = ~7 sentences × ~80 chars × 10 bits = 5600 bits per cycle
- At 9600 baud, ~580 ms just for GSV — pushed to 5-s intervals to fit
- **Recommendation:** raise baud to 38 400 (UBX-CFG-VALSET command, then UBX-CFG-CFG to save to BBR) for headroom.

## Registers / Configuration

The MAX-M10S is configured via **UBX commands** (binary protocol), not by direct register writes. There is **no register map exposed to the host** in the conventional sense. Key configuration commands the firmware will use:

| Command | Purpose | Notes |
|---|---|---|
| **UBX-CFG-VALSET** | Modern key-value configuration | Replaces deprecated UBX-CFG-PRT, CFG-RATE, etc. M10 firmware preferred. |
| **UBX-CFG-VALGET** | Read current configuration values | |
| **UBX-CFG-CFG** | Save/load/clear configuration sections to/from BBR (backup RAM) or Flash | Use to persist baud rate, message rate, GNSS selection across resets. |
| **UBX-NAV-PVT** | One-shot navigation solution: UTC time, lat/lon, alt, vel, heading, accuracy, fix type | **Recommended primary nav read** in FW |
| **UBX-NAV-TIMEUTC** | UTC time + accuracy | Useful for RTC discipline |
| **UBX-NAV-STATUS** | Fix type, time-to-fix, current power mode | Diagnostic |
| **UBX-NAV-SAT** | Per-satellite info (signal strength, used-in-fix) | Diagnostic |
| **UBX-RXM-PMREQ** | Request power-management transition (e.g., enter software standby) | **Critical** for low-power use |
| **UBX-MGA-INI-TIME_UTC** | Inject UTC time from host (e.g., from RTC) | Speeds up TTFF (warm start hint) |
| **UBX-MGA-INI-POS_LLH** | Inject position estimate | Speeds up TTFF |
| **UBX-MGA-***| AssistNow ephemeris/almanac injection | Requires internet or pre-loaded data |
| **UBX-CFG-TP5** | Configure TIMEPULSE | Default = 1 Hz aligned to GPS time after fix |

**Authoritative source:** `u-blox M10 SPG 5.10 Interface description` (UBX-21035062) [p. 22 Related documents]. **Required reading for FW development** beyond basic NMEA parsing.

## Initialization sequence

```
1. (Hardware) +3.2 V applied to V_CC (pin 8), V_IO (pin 7). VIO_SEL (pin 15) open
   = selects 3.3 V mode. V_BCKP supercap charging. RESET_N rises to V_IO via internal pullup.
2. **Inrush**: up to 100 mA for a few ms — TPS62840 must absorb this transient.
3. Wait t_startup (datasheet silent; from u-blox AppNote: ~1 s to first NMEA on UART).
4. (Optional but recommended) Inject startup aids:
     a. UBX-MGA-INI-TIME_UTC from PCF85063A RTC → cuts cold-start time to "warm start"-class
     b. UBX-MGA-INI-POS_LLH from last-known position (if stored in ESP NVS)
5. (One-time, per board) Configure non-default behavior via UBX-CFG-VALSET:
     - Baud rate → 38400 (or 115200)
     - Disable NMEA output (use UBX-NAV-PVT only); or curate which NMEA sentences emit
     - GNSS selection (default GPS+GAL+BDS B1I + QZSS + SBAS is reasonable)
     - Power-save mode preferences
     Then UBX-CFG-CFG to save to BBR.
6. Wait for first fix: monitor UBX-NAV-PVT → fixType ≥ 2 (2D or 3D fix).
     - Cold start (no aids): 23–28 s typical, clear sky
     - With time + position aids: as fast as a warm start (~1 s if ephemeris valid)
7. Once fix achieved:
     - TIMEPULSE (1 PPS) becomes accurate (RMS 30 ns vs GPS time)
     - GPS UTC time becomes valid → use to discipline RTC
8. Steady-state: read UBX-NAV-PVT at 1 Hz (or higher up to 10 Hz) for nav data.
```

**Persistence:** the BBR (backup RAM) retains configuration AND ephemeris/almanac as long as **V_BCKP holds ≥ 1.65 V**. With v7.2's 0.22 F supercap + 28 µA backup draw, that's ~3.6 hours after V_CC removal.

## Operation

### Reading navigation data

**Default path (NMEA, simplest):**
```
1. Read lines from UART
2. Parse $GxRMC (UTC time, status, lat/lon, speed, course, date)
3. Parse $GxGGA (lat/lon, fix quality, # satellites, altitude)
4. Parse $GxVTG (track, ground speed)
5. Wait for next sentence...
```

**Recommended path (UBX, efficient):**
```
1. Request periodic UBX-NAV-PVT at desired rate (1 Hz default, up to 10 Hz)
2. On each PVT message:
     - validate sync chars + checksum
     - extract: iTOW, fixType, lon/lat/height, gSpeed, headMot, hAcc, vAcc
     - check fixType: 0=no fix, 2=2D, 3=3D, 4=GNSS+dead-reckoning, 5=time-only
3. No need to parse NMEA — full nav info in one binary packet
```

### Time disciplining of RTC

```
1. GPS achieves first fix (UBX-NAV-PVT fixType ≥ 2)
2. Read UBX-NAV-TIMEUTC → year, month, day, hour, min, sec, nanoseconds, valid flags
3. If valid_flag (UTC_VALID = 1):
     - On next TIMEPULSE rising edge (interrupt on ESP-S3 GPIO46):
         - Snapshot the just-received UTC time (incremented by 1 second to align with PPS)
         - Write to PCF85063A RTC (registers 0x04–0x0A) within the next < 1 s window
     - RTC is now within ~30 ns of GPS time at the PPS edge
4. Repeat opportunistically (e.g., once per hour) to compensate RTC drift (~1 ppm)
```

### Power management

**Available modes:**
| Mode | Power | How to enter | How to exit | Use case |
|---|---|---|---|---|
| **Continuous tracking** | 9.5–10 mA @ 3.0 V | Default at power-up | — | Active navigation, hiking, running |
| **PSM cyclic tracking** | ~5 mA @ 3.0 V | UBX-CFG-VALSET PSM=cyclic | — | Asset tracking with 1 Hz fix rate, less power |
| **Software standby** | 120 nA on V_CC, 37–46 µA on V_IO | UBX-RXM-PMREQ command | EXTINT pin or UART activity | "GPS off but BBR alive, ready to wake" |
| **Hardware backup** | 28 µA total (V_BCKP only) | Cut V_IO 100 ms before V_CC | Re-apply V_CC + V_IO | "GPS off, ephemeris preserved on supercap" |
| **Fully off** | 0 | Cut all rails including V_BCKP | Cold start required | Long-term storage |

**Recommended wearable strategy:** keep GPS in **hardware backup** when not actively navigating (LNA_EN GPIO toggled off, V_CC switched off via a load-switch — *not currently in v7.2 — see Open Q6*). Wake to continuous tracking when user opens "outdoor activity" mode. With recent ephemeris in BBR, TTFF will be ~1 s (hot start) instead of ~25 s.

**Critical: V_IO / V_CC switching order** [p. 11 §4.2 warning]:
> For designs with 1.8 V supply at V_IO and V_BCKP supplied, **switch off the V_IO supply 100 ms before V_CC** when transitioning to the hardware backup mode. Alternatively, put the receiver to software standby mode by sending the UBX-RXM-PMREQ message before switching off V_IO and V_CC. **For designs with 3 V supplies, both supplies can be switched off simultaneously.**

→ For v7.2 (3.2 V supplies), simultaneous shutoff is allowed. Good.

### Wearable budget implications

- **GPS off (default state):** 28 µA on V_BCKP from supercap; 0 from main rail. Negligible.
- **GPS hot-start fix burst:** ~14 mA × 1 s = 14 mC. Negligible per event.
- **GPS continuous tracking** (5–10 min "navigation session"): **~12 mA continuous** — this is **the dominant load** on the 3.2 V rail when active.
- **GPS PSM cyclic:** 7 mA average — useful for background tracking (jog logging).

At 300 mAh battery → continuous GPS tracking = 25 hours straight; PSM cyclic = 42 hours. For a typical "30 min outdoor activity" GPS session per day, total daily GPS energy = ~6 mAh = 2 % of battery. **Acceptable.**

## Datasheet notes

- **Module size**: 10.1 × 9.7 × 2.5 mm + 0.76 mm tab. **~98 mm² footprint** — likely the dominant PCB-area constraint on v7.2. Plan layout around it.
- **Two product variants** [p. 21 §9.3]: MAX-M10S-00B (global, Mass production), MAX-M10S-00B1 (regional, Initial production). v7.2 BOM probably uses **00B-01**. Both run **ROM SPG 5.10** firmware. Confirm.
- **Inrush 100 mA** is the **single biggest transient load** in the whole wearable. Plan rail design accordingly. TPS62840 750 mA rating absorbs it, but transient drop on the 3.2 V rail is a function of bulk capacitance — verify with scope on bring-up.
- **GNSS combinations:** default = GPS + Galileo + BeiDou B1I (+ QZSS + SBAS auto). For "GPS-only" lower power: ~7.5 mA tracking (vs 9.5 mA multi-constellation). **BeiDou B1I cannot be enabled simultaneously with BeiDou B1C or GLONASS L1OF** [p. 6 footnote 13].
- **AssistNow services** [p. 5 Table 5]:
  - Live Orbits → real-time ephemeris injection (internet required at request time)
  - Predictive Orbits → pre-computed multi-day orbit predictions (offline use after download)
  - Autonomous → self-computed orbit prediction (no internet, up to 2 days valid)
  Without internet, **AssistNow Autonomous + RTC time injection** is the best practical TTFF boost — reduces cold start from 28 s to ~4 s.
- **NMEA 4.11** is the default; offers extensions (signal-quality indicators, multi-GNSS talker IDs $GN... instead of $GP...).
- **Anti-jamming + anti-spoofing reporting** [p. 7 Table 9]: receiver can flag interference/spoof events. Useful for "this fix may be unreliable" annotation.
- **Configuration lockdown**: can lock config by command — prevents tampering. Not needed for v7.2.
- **Secure boot**: only signed FW images are executed. Not user-tunable.
- **MSL 4** [p. 18 Table 22]: floor life 72 h. Same handling as VEML6030.
- **Qualifications:** AEC-Q104 subset (automotive class, but not full Q100 — "professional grade").
- **Antenna note**: the integrated LNA + SAW gives the part its **passive-antenna-friendly** advantage. With a 25 × 4 mm patch or chip antenna on the L1 band, expect typical CEP 2–3 m in open sky. A high-quality active antenna (LNA in the antenna head) improves urban-canyon and indoor near-window performance.
- **Operating temp:** −40 to +85 °C — wrist-worn fine.

## Open questions

- **Q1 — UART baud rate at boot.** Default = 9600. Recommend FW init bumps to **38 400 or 115 200** for headroom + responsiveness. **Action:** choose 38 400 (good compromise) and codify in init sequence. Persist via UBX-CFG-CFG.
- **Q2 — RTC-discipline cadence.** How often should FW push GPS UTC into the PCF85063A RTC? Each fix? Once per hour? Once per session? **Action:** product decision. Recommend: on first fix per power session + opportunistically every 60 min when GPS is active.
- **Q3 — Backup supercap sizing.** 0.22 F = 3.6 h retention. Upgrade to 1.0 F (≈ 16 h, covers overnight)? Or feed V_BCKP from main battery via a diode (≈ days, costs ~3 µA from main battery continuously)? **Action:** decide based on user behavior model. If the watch is worn 24/7 and only off-battery during charging (≤ 2 h), 0.22 F is enough. If the watch sits overnight on a nightstand off-wrist, larger cap or battery-fed V_BCKP needed.
- **Q4 — NMEA vs UBX primary protocol.** Recommend **UBX-NAV-PVT** as the primary nav source (binary, one-message-everything, cheap to parse). Keep NMEA TXT enabled for boot diagnostics. **Action:** FW design decision.
- **Q5 — GPS antenna identification.** The BOM-referenced "Antenna-2450AT18A0100001E" is 2.4 GHz (Wi-Fi/BT) — **wrong band for GPS**. Which line item on v7.2 is the actual L-band GPS antenna? **Action:** **urgent schematic + BOM review by Ivan**. Without a proper L-band antenna, the GPS will not fix.
- **Q6 — GPS rail switching.** Currently the 3.2 V rail is always on (TPS62840 EN tied to SYS). To save power when GPS is unused, would it help to add a load-switch (P-channel MOSFET or dedicated LDO) on the GPS V_CC, controlled by an ESP GPIO? **Trade-off:** saves ~9 mA when GPS off (versus ~30 µA software-standby) — but software standby is much simpler. **Recommendation:** stick with software-standby + V_BCKP supercap for v7.2; revisit if battery life proves marginal.
- **Q7 — EXTINT routing.** Pin 5 (EXTINT) is currently unrouted (assumed). If FW wants to wake the GPS from software-standby via a GPIO toggle (faster than sending a UART command), route EXTINT to a spare ESP GPIO. Not blocking. **Action:** consider for v7.3.
- **Q8 — AssistNow strategy for fast TTFF.** Without internet, **AssistNow Autonomous** (self-computed orbit prediction) + injected RTC time gives ~4 s TTFF cold-start. **Action:** enable AssistNow Autonomous in FW init via UBX-CFG-VALSET. Big TTFF win for "user opens GPS app" UX.
- **Q9 — TIMEPULSE-GPIO46 boot sequencing.** WARN-05 — confirm ESP-S3 GPIO46 is **input** when V_CC rises on MAX-M10S, to avoid accidentally entering safe-boot. **Action:** ESP-S3 boot strapping check (GPIO46 is also a strapping pin — confirm boot-time level is HIGH or HiZ).
