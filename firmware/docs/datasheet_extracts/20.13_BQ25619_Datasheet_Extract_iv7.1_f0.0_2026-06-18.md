## Critical finding (read this first)

**The BQ25619 has NO battery voltage ADC.** The complete I²C register map is REG00–REG0C (13 registers, p. 32). REG0B is the Part Information register, not a VBAT readout. There is **no register anywhere in the chip that reports the measured battery voltage to the host.**

This directly contradicts two things:
1. **v7.2 §POWER ARCHITECTURE** ("Battery voltage: read via I²C BATSNS (no external ADC)") — wrong. BATSNS (pin 10) is an *analog* remote-sense input the IC uses to close its own CV regulation loop. It is not exposed to I²C.
2. **The porting doc** `BQ25619_2026-06-11_iv7.1.f0.0.md` line 82 and DEFECT-005 — `BQ25619_REG_VBAT_ADC (0x0B)` does not exist. 0x0B is REG0B Part Information. There is no VBAT ADC and no scaling formula to verify.

**Consequence for firmware:** SoC has to come from somewhere else. Three options:
- Add an ESP32-S3 ADC channel onto the BAT/SYS rail through a divider (board change).
- Infer voltage indirectly from charger state bits (CHRG_STAT, VBUS_STAT, BAT_FAULT, VSYS_STAT) and assume voltage by state. Coarse — usable for "charging / done / low battery" UI, not for a percentage indicator.
- Use a different IC variant or add a dedicated fuel gauge (e.g., BQ27xxx).

This is a hardware-architecture-level gap and **must be flagged for v7.2 correction and PCB review** before silicon.

### Firmware-critical bit fields (only ones FW touches today)

**REG00 (0x00) Input Current Limit** [p. 33]
- `[7] EN_HIZ` — 1 = HIZ mode (RBFET/REGN/bias off, system runs from battery only)
- `[6] TS_IGNORE` — 1 = ignore TS pin (NTC_FAULT reports normal)
- `[5] BATSNS_DIS` — 1 = use BAT pin for CV regulation instead of BATSNS
- `[4:0] IINDPM[4:0]` — input current limit; offset 100 mA, step 100 mA, range 100 mA (00000) – 3.2 A (11111). Reset 10111 = 2.4 A.

**REG01 (0x01) Charger Control 0** [p. 34]
- `[7] PFM_DIS` — 1 = disable PFM (always PWM)
- `[6] WD_RST` — write 1 to kick watchdog; auto-clears
- `[5] BST_CONFIG` — 1 = boost mode enabled (gated by adapter presence — see Operation/Boost)
- `[4] CHG_CONFIG` — 1 = charging enabled (gated by /CE and ICHG ≠ 0)
- `[3:1] SYS_MIN[2:0]` — minimum system voltage. Reset 101 = 3.5 V. Range 2.6–3.7 V in 0.1 V steps.
- `[0] MIN_VBAT_SEL` — 0 = V_BAT exit-boost falling 2.8 V (default); 1 = 2.5 V

**REG02 (0x02) Charge Current Limit** [p. 35]
- `[7] Reserved` — POR = 1
- `[6] Q1_FULLON` — 1 = Q1 fully on for efficiency when IINDPM < 700 mA; 0 = partial-on for regulation accuracy (default)
- `[5:0] ICHG[5:0]` — fast charge current; step 20 mA, offset 0 mA. Reset 010001 = 340 mA. Max 111011 = 1180 mA, then 111100=1290, 111101=1360, 111110=1430, 111111=1500 mA. **000000 disables charge.**

**REG03 (0x03) Precharge / Termination** [p. 36]
- `[7:4] IPRECHG[3:0]` — precharge current; step 20 mA, offset 20 mA, range 20–260 mA. Reset 0001 = 40 mA. Values above 1100 are clamped to 260 mA.
- `[3:0] ITERM[3:0]` — termination current; step 20 mA, offset 20 mA, range 20–260 mA. Reset 0010 = 60 mA. Clamped at 1100. **For ~200 mAh LiPo, set ITERM = 20 mA (0000) for the advertised "20 mA low termination" benefit.**

**REG04 (0x04) Battery Voltage Limit** [p. 37]
- `[7:3] VBATREG[4:0]` — CV regulation target; step 10 mV, range 3.504 V (00000) – 4.300 V (11111). Beyond: 01110→4.350 V, 10011→4.400 V, 11000→4.450 V, 11101→4.500 V. Reset 01000 = 4.200 V. **For a standard 3.7 V LiPo, 4.20 V is the safe choice.**
- `[2:1] TOPOFF_TIMER[1:0]` — 00 disabled (default), 01 = 15 min, 10 = 30 min, 11 = 45 min
- `[0] VRECHG` — 0 = 120 mV below VREG (default), 1 = 210 mV below

**REG05 (0x05) Charger Control 1** [p. 38]
- `[7] EN_TERM` — 1 = termination enabled (default)
- `[5:4] WATCHDOG[1:0]` — 00=disable, 01=40 s (default), 10=80 s, 11=160 s. **If FW kicks the watchdog, registers retain host-mode values. If FW lets it expire, the chip falls back to default mode.**
- `[3] EN_TIMER` — 1 = safety timer enabled (default)
- `[2] CHG_TIMER` — 0=20 hr, 1=10 hr (default)
- `[1] TREG` — 0=90 °C, 1=110 °C (default) — junction temp thermal regulation point
- `[0] JEITA_VSET` — 0 = 4.1 V max in JEITA warm zone (default), 1 = VREG

**REG06 (0x06) Charger Control 2** [p. 39]
- `[7:6] OVP[1:0]` — VACOV threshold. 00=5.85, 01=6.4 (5 V input), 10=11 (9 V input), 11=14.2 (12 V, default).
- `[5:4] BOOSTV[1:0]` — 00=4.6 V, 01=4.75 V (POR), 10=5.0 V, 11=5.15 V. **For 5 V LED loads, set BOOSTV = 10 (5.0 V).**
- `[3:0] VINDPM[3:0]` — input voltage limit; step 100 mV, offset 3.9 V, range 3.9–5.4 V. Reset 0110 = 4.5 V.

**REG07 (0x07) Charger Control 3** [p. 40]
- `[7] IINDET_EN` — write 1 to re-run PSEL/IINDPM detection
- `[6] TMR2X_EN` — 1 = safety timer slowed 2× during DPM/JEITA/thermal (default)
- `[5] BATFET_DIS` — **set to 1 to enter ship mode (with BATFET_DLY=1, delays t_BATFET_DLY then BATFET off)**
- `[4] BATFET_RST_WVBUS` — 0 = full system reset requires adapter to be removed (default); 1 = reset works with adapter present
- `[3] BATFET_DLY` — 0 = BATFET off immediately when BATFET_DIS=1; 1 = wait t_BATFET_DLY (10–15 s, default)
- `[2] BATFET_RST_EN` — 1 = QON full-system-reset enabled (default)
- `[1:0] VINDPM_BAT_TRACK[1:0]` — 00 = disabled (use VINDPM register), 01/10/11 = VBAT + 200/250/300 mV

**REG08 (0x08) Charger Status 0** [p. 41] — read only
- `[7:5] VBUS_STAT[2:0]` — 000 = no input, 001 = USB SDP (500 mA), 011 = adapter (2.4 A), 111 = Boost mode (active)
- `[4:3] CHRG_STAT[1:0]` — 00 = not charging, 01 = pre-charge/trickle, 10 = fast charge (CC or CV), 11 = charge termination done
- `[2] PG_STAT` — 1 = power good
- `[1] THERM_STAT` — 1 = in thermal regulation
- `[0] VSYS_STAT` — 1 = SYS in SYS_MIN regulation (V_BAT < SYS_MIN)

**REG09 (0x09) Charger Status 1** [p. 42] — read only, latches faults
- `[7] WATCHDOG_FAULT` — 1 = watchdog expired (back to default mode)
- `[6] BOOST_FAULT` — 1 = boost mode fault (BST_OVP, BST_BAT depleted, BST_OCP)
- `[5:4] CHRG_FAULT[1:0]` — 00 normal, 01 input fault, 10 thermal shutdown, 11 safety timer expiration
- `[3] BAT_FAULT` — 1 = battery overvoltage (>104% VREG)
- `[2:0] NTC_FAULT[2:0]` — buck mode: 000 normal, 010 warm, 011 cool, 101 cold, 110 hot; boost mode: 000/101/110 only

**REG0A (0x0A) Charger Status 2** [p. 43]
- `[7] VBUS_GD` — 1 = VBUS passes poor-source detection (~3.8 V, 30 mA load)
- `[6] VINDPM_STAT` — 1 = in VINDPM regulation
- `[5] IINDPM_STAT` — 1 = in IINDPM regulation
- `[4] BATSNS_STAT` — 1 = BATSNS open/short detected; using BAT pin instead
- `[3] TOPOFF_ACTIVE` — 1 = top-off timer counting
- `[2] ACOV_STAT` — 1 = in VACOV
- `[1] VINDPM_INT_MASK` (R/W) — 1 = block /INT pulse on VINDPM events
- `[0] IINDPM_INT_MASK` (R/W) — 1 = block /INT pulse on IINDPM events

**REG0B (0x0B) Part Information** [p. 44]
- `[7] REG_RST` — write 1 to reset all registers to POR and reset safety timer (auto-clears)
- `[6:3] PN[3:0]` — part number, reserved bit pattern (POR pattern = 0010 1 from bits 6:2 of value 2Ch)
- `[2:0] Reserved`

**REG0C (0x0C) Charger Control 4 (JEITA)** [p. 45]
- `[7:6] JEITA_COOL_ISET[1:0]` — T1-T2 cool zone current: 00 no charge, 01 = 20% ICHG (default), 10 = 50%, 11 = 100% (no 2× timer slowdown)
- `[5:4] JEITA_WARM_ISET[1:0]` — T3-T5 warm zone current: 00 no charge, 01 = 20%, 10 = 50%, 11 = 100% (default, no slowdown)
- `[3:2] JEITA_VT2[1:0]` — T2 threshold: 00=5.5 °C, 01=10 °C (default), 10=15 °C, 11=20 °C
- `[1:0] JEITA_VT3[1:0]` — T3 threshold: 00=40 °C, 01=44.5 °C (default), 10=50.5 °C, 11=54.5 °C

## Initialization sequence

```
1. Wait for POR (host-side: device powers up when VBUS>V_VBUS_UVLOZ or VBAT>V_BAT_DPLZ).
2. (Optional) Force register reset: REG0B[7] = 1. Returns to 0 automatically. [p. 44]
3. Configure watchdog policy:
   - If FW will not kick: set REG05[5:4] = 00 (disable watchdog). Otherwise chip
     reverts to default mode after 40 s and rewrites WATCHDOG-reset bits to POR.
   - If FW will kick: leave default 01 (40 s) and write WD_RST=1 (REG01[6]) every <40 s.
     [p. 31 watchdog flow]
4. Set input current limit (IINDPM) per source:
   - If PSEL strapped LOW (adapter), POR already gives 2.4 A.
   - Override via REG00[4:0] if a different limit needed (e.g., 500 mA for USB SDP). [p. 33]
5. Set charge current: REG02[5:0] = (mA / 20). Example: 500 mA = 011001b = 0x19. [p. 35]
   For our ~200 mAh LiPo, recommend ICHG = 200 mA (0001010b) = 1C limit.
6. Set termination current low for small LiPo:
   REG03[3:0] = ITERM = 20 mA (0000). [p. 36]
7. Set CV regulation voltage:
   REG04[7:3] = VBATREG = 01000 for 4.20 V (POR). Confirm cell datasheet permits.
8. (Optional) Set top-off timer for full-charge: REG04[2:1] = 01 (15 min). [p. 37]
9. Set VINDPM: REG06[3:0] = 0110 (4.5 V, POR) — or enable VINDPM_BAT_TRACK
   in REG07[1:0] for battery-following input regulation. [p. 39, 40]
10. Set BOOSTV target for PMID 5 V loads:
    REG06[5:4] = 10 (5.0 V). [p. 39]
11. Configure /INT masking — leave defaults (REG0A[1:0]=00) to receive all events. [p. 43]
12. Set JEITA cool/warm action if used:
    REG0C[7:6] = 10 (50% ICHG at cool, more aggressive than 20% default)
    REG0C[5:4] = 11 (100% ICHG at warm; default).
    Set TS_IGNORE = 1 (REG00[6]) if NTC divider on board is wrong — better than
    false suspend.
13. Enable charging: REG01[4] = 1 (CHG_CONFIG). Boost stays disabled until call to
    bq25619_set_boost(true) which sets REG01[5] = 1 (BST_CONFIG).
14. Probe REG09/REG0A immediately after init to clear any latched POR-time faults.
```

**Timing:** All register writes complete in well under one I²C transaction (~30 µs @ 400 kHz / 2 bytes addr+data). Typical full init = ~12 single-byte writes = under 1 ms wall time. The 220-ms REGN-LDO ramp is one-shot on chip startup, not gated by I²C.

## Operation

### Charging state machine [p. 21–22]

Five phases: **battery short → pre-charge → fast charge (CC) → fast charge (CV) → top-off trickle (optional)**.

| V_BAT range | Mode | Current | CHRG_STAT bits |
|---|---|---|---|
| < V_BAT_SHORT (2.0–2.15 V falling) | Battery short trickle | 25 mA typ (I_BAT_SHORT) | 01 |
| V_BAT_SHORTZ → V_BATLOWV (~2.25 → ~3.0 V) | Pre-charge | IPRECHG (REG03[7:4]) | 01 |
| > V_BATLOWV (~3.12 V rising) | Fast charge CC | ICHG (REG02[5:0]) | 10 |
| V_BAT ≈ VBATREG | Fast charge CV | reducing | 10 |
| Below ITERM & ≥ V_RECHG | Termination → done | 0, top-off timer if enabled | 11 |
| Below VRECHG threshold | Restart | new cycle | 10 |

When termination occurs: STAT pin goes HIGH, CHRG_STAT = 11, /INT pulses. The converter keeps running to power SYS — BATFET only turns off in shutdown.

### Boost mode operation [p. 19]

**Enable conditions (all required):**
1. BATFET_DIS = 0, CHG_CONFIG = 0, BST_CONFIG = 1.
2. V_BAT above V_BST_BAT (~2.8 V rising / 2.5 V falling per MIN_VBAT_SEL).
3. VBUS less than V_BAT + V_SLEEP (i.e., **no adapter plugged in**).
4. TS pin in V_BHOT_RISE% < V_TS < V_BCOLD_FALL% range (or TS_IGNORE=1).

VBUS_STAT bits go to **111** when actively boosting. PMID is regulated to BOOSTV setting.

**Critical operational rule:** *Boost and charge are NOT manually toggled by FW per state change.* Per p. 19: *"The charger automatically transitions between charging mode and Boost mode by setting BST_CONFIG bit and CHG_CONFIG bit both to 1. When the adapter plugs in and the conditions to start a new charge cycle are valid, the device is in charging mode. If the adapter is removed and the boost enable conditions are valid, the device transits to Boost mode automatically."*

**So the firmware policy is:**
- Set BST_CONFIG = 1 when any PMID-powered load is enabled (or always, if you want PMID available whenever USB is unplugged).
- Set BST_CONFIG = 0 when no PMID load needs +5 V (saves quiescent — boost converter remains in standby otherwise).
- CHG_CONFIG stays = 1 always (battery should always be allowed to charge when an adapter is present).
- The HW does the arbitration.

### Boost fault paths [p. 28]

- **BST_OVP** (V_PMID > 5.55–6.15 V): chip stops switching, BST_CONFIG cleared to 0, BOOST_FAULT set in REG09[6], /INT pulse. **FW must re-set BST_CONFIG to re-enable.**
- **BST_OCP / I_SYS_OCP_Q4** (>5–6 A discharge through Q4): latches off Q4 in 100 µs, BOOST_FAULT set. Exit by Ship-mode-exit methods.
- **BST_BAT** (V_BAT falls below V_BST_BAT 2.4–2.6 V): boost suspends.
- **Thermal**: T_J > 150 °C suspends boost; recovers at 145 °C. BST_CONFIG cleared. FW must re-arm.

### Ship-mode entry [p. 25]

**Two paths:**
1. **No adapter:** write BATFET_DIS=1 (REG07[5]) — BATFET turns off either immediately (BATFET_DLY=0) or after t_BATFET_DLY (10–15 s, default).
2. **Adapter present:** must first set BATFET_RST_WVBUS=1 (REG07[4]), then BATFET_DIS=1. Charger turns off BATFET while adapter still attached; when adapter is removed, charger enters ship mode.

**Effect:** BATFET (Q4) opens, disconnecting battery from SYS. System power drops. I_SHIP_BAT = 7 µA typ, 9.5 µA max (BATSNS, BAT, SYS, SW combined leakage) [p. 8].

### Ship-mode exit (BATFET enable) [p. 25]

Any of:
1. Plug in adapter (VBUS rises).
2. Host clears BATFET_DIS bit (only works if BATFET is already on for some other reason).
3. Host writes REG_RST=1 in REG0B[7] (resets all regs including BATFET_DIS).
4. **/QON pin pulled LOW for t_SHIPMODE (0.9–1.3 s).** Hardware path — works without host. **EN_HIZ is forced to 1** until adapter plugs in (then auto-cleared). FW must clear EN_HIZ before re-enabling boost.

### Full system reset via /QON [p. 25]

When BATFET_RST_EN=1 (default) and /QON pulled LOW for **t_QON_RST (8–12 s)**:
- BATFET turns off for t_BATFET_RST (250–400 ms).
- Re-enabled, system power-cycles, all registers reset to POR.
- If BATFET_RST_WVBUS=0 (default), this only works when adapter is removed.
- If BATFET_RST_WVBUS=1, works either way (chip enters HIZ first, then resets).

**Firmware implication for the QON button on GPIO16 (per v7.2):** The ESP sees the button as a normal GPIO input, but if the user holds it for 8–12 seconds, the BQ25619 will yank power out from under the ESP. Document this in the user manual. A short press is purely an ESP-side event.

### Watchdog (regs 5 [4]) [p. 31]

After POR, watchdog timer is enabled by default at 40 s.
- If FW never writes any register, chip stays in **Default mode** (WATCHDOG_FAULT=1), continues charging with POR settings.
- The first I²C write puts chip in **Host mode** (WATCHDOG_FAULT=0).
- In Host mode, FW must write WD_RST=1 (REG01[6]) before the watchdog expires, or all WATCHDOG-resettable bits revert to POR (chip drops back to Default mode). Critically, this resets ICHG, IPRECHG, ITERM, VBATREG, EN_TERM, CHG_CONFIG, BST_CONFIG, and the JEITA registers. **Forgetting to kick watchdog will silently re-enable charging / reset settings.**
- Alternative: set WATCHDOG[1:0] = 00 to disable. Recommended for our use case if FW does not have a reliable 1-Hz periodic task hitting the BQ.

### Polling cadence guidance

Per the porting doc, the FW polls every 1 s. Useful read set:
- REG08 (Status 0, 1 byte): VBUS_STAT, CHRG_STAT, PG_STAT, THERM_STAT, VSYS_STAT
- REG09 (Status 1, 1 byte): all faults
- REG0A (Status 2, 1 byte): IINDPM/VINDPM/BATSNS/TOPOFF/ACOV status
- WD_RST kick: REG01[6] = 1 (1 byte write, with RMW since other bits live there)

**Per cycle total:** ~3 reads + 1 RMW write = ~6 byte transactions ≈ 250 µs of bus time at 400 kHz. Negligible.

## Interrupts

The chip exposes **one** /INT pin (pin 7) — open-drain, active-low, 256-µs pulse per event [p. 26].

| Event | /INT pulse | Notes |
|---|---|---|
| Good input source detected (V_VBUS > V_BAT, V_VBUS < V_ACOV, V_VBUS > V_POORSRC) | yes | p. 26 |
| Input adapter removed | yes | p. 27 |
| USB/adapter source identified | yes | After PSEL detection |
| Charge complete | yes | CHRG_STAT 11 |
| Any fault in REG09 | yes | Latches |
| VINDPM/IINDPM event | yes (maskable via REG0A[1:0]) | Default unmasked |
| Top-off timer start/expire | yes | — |

**Reading status:** REG09/REG0A latch fault/status info from last read. To get *current* state, FW must read each register **twice** consecutively — the first read reports any pre-existing latched values, the second read reports current. [p. 31]

**In v7.2, /INT is not connected to ESP** so the host never sees these pulses. Status is sampled by polling at 1 Hz. **Trade-off:** events that come and go in <1 s between polls (e.g., a brief brown-out → recover) are missed. The latched status registers REG09 mitigate this for *faults* (they stay latched until read), but transient PG_STAT changes are not latched and can be missed.

**Recommendation for v7.2 review:** route /INT to a spare ESP GPIO for sub-second event response — the routing change is one trace + a 10 kΩ pull-up to the ESP's 3V3, no FW change required initially (firmware can keep polling). Would benefit ship-mode exit confirmation in particular.

## Datasheet notes

- **No fuel gauge.** The BQ25619 has no coulomb counter, no battery ADC, no VBAT readback register. Anyone shopping for an off-chip-coulomb-counter integration needs to add a separate IC (e.g., BQ27xxx, MAX17048) or use the ESP's ADC on a battery divider. [p. 32 register table]
- **Default-mode autonomy.** After POR with no host writes, the chip charges with 340 mA / 4.20 V / JEITA enabled / 10-hr safety timer — and *just works*. This is intentional for the wearable use case where the host may be asleep. [p. 31]
- **Watchdog quirk.** Several control bits are reset *by watchdog expiry* (column "Reset" = "by Watchdog" in the register tables). Notably: WATCHDOG bits themselves, EN_TERM, EN_TIMER, CHG_TIMER, TREG, JEITA_VSET, JEITA registers, IINDET_EN, TMR2X_EN, BATFET_RST_EN, BATFET_RST_WVBUS, all of ICHG, IPRECHG, ITERM, VBATREG, TOPOFF, VRECHG, and CHG_CONFIG. **If watchdog expires, charging continues but with POR settings.** This is by design — guards against host hangs.
- **Watchdog NOT reset by I²C transactions alone** — you must write WD_RST=1 to REG01[6]. [p. 31 fig 7-15]
- **Q1 (RBFET) is OFF during boost mode** [p. 19], preventing reverse current to a non-connected VBUS. PMID stays clean.
- **Bad-adapter detection** runs every 2 s on VBUS rise and pulls 30 mA against a >3.9 V floor [p. 17]. If your adapter is weak/loose, watch /INT pulses tied to PG_STAT toggles.
- **BATSNS open/short detection** runs automatically. If BATSNS is left floating or shorted to GND, BATSNS_STAT (REG0A[4]) goes high and the chip falls back to BAT-pin regulation. Safe failure mode. [p. 21, 43]
- **STAT pin polarity** drives a charge LED: LOW=charging, HIGH=done, 1 Hz blink=fault. Pure on-PCB UI feature. Per v7.2, not used. Can be left floating or removed.
- **PSEL latched by PSEL-pin level on adapter detection.** Once IINDPM is set by PSEL, host can override via REG00 — but if PSEL changes mid-session, IINDET_EN must be written to re-run detection. [p. 18, 40]
- **VINDPM_BAT_TRACK** lets input voltage limit follow VBAT, useful for high-resistance USB cables: with V_BAT=3.6 V and TRACK=01 (VBAT+200 mV), VINDPM = 3.8 V (vs default 4.5 V), letting weak adapters keep delivering current. Recommend enabling for cable robustness. [p. 18, 40]
- **System load during USB plug-in is auto-limited to 200 mA** until SYS rises above V_BAT_SHORTZ [p. 18]. Important: at first connection with deeply discharged battery, do not assume full IINDPM is available.
- **TOP_OFF_TIMER** continues holding CHRG_STAT=11 (termination) but lets a small extra charge slip in past ITERM. Setting it to 15 min boosts full-charge accuracy for small cells. [p. 22]
- **Supplement mode** (system load > input limit) lets BAT and VBUS both source SYS. Helpful for transient LED load spikes during USB charging. Automatic when SYS drops below V_BAT. [p. 20]

## Open questions

1. **Battery voltage source for SoC.** With no BQ VBAT readback, the entire `bq25619_read_vbat_mv` / `bq25619_soc_from_mv` chain in the porting doc is non-functional. **Action:** Ivan decides — add an ESP32-S3 ADC channel (board change before fab), use coarse charge-state-driven SoC, or add a fuel-gauge IC. This is the single highest-impact decision for Phase 3.
2. **PSEL strap value.** v7.2 does not specify. **Recommend LOW (2.4 A default IINDPM)** — host can lower the limit immediately at init if needed.
3. **/CE strap value.** v7.2 does not specify. **Recommend LOW** (tie to GND, CHG_CONFIG bit gates from FW). Or route to ESP GPIO for hardware-level disable.
4. **TS network correction.** Confirm with Ivan whether to (a) change R_T1/R_T2 to TI-recommended values in v7.2 / next PCB rev, or (b) set TS_IGNORE=1 in FW and monitor cell temp via a separate ESP ADC + NTC pair. Action: Ivan, based on PCB fab status.
5. **/INT routing.** Worth a v7.3 rework? Reduces missed-event probability and improves ship-mode-exit confirmation. Action: defer to first-silicon bench tests; decide based on observed polling latency issues.
6. **Watchdog policy.** Default-disable at init (safer if FW polling crashes) or default-enable with 1 Hz kick (autonomous fail-safe to known-good charging)? **Recommend disable** for the wearable use case — FW polling failure should be observable elsewhere, and the WD-reverted POR ICHG of 340 mA is more than 200 mAh cell wants anyway.
7. **Top-off timer.** Recommend enable at 15 min (REG04[2:1]=01) — improves full-charge percentage and is harmless on a small cell. Confirm with Ivan.
8. **BOOSTV target.** 5.0 V (BOOSTV=10) or stay at POR 4.75 V (BOOSTV=01)? Depends on MAX30101 LED forward drop + WS2812 spec (5.0 V nominal). **Recommend 5.0 V.**
