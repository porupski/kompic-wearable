## Critical findings (read this first)

### 1. CSB pin MUST be tied to V_DDIO for I²C mode [p. 45, 46, 52]

The BME688 supports both I²C and SPI. Interface auto-selects based on CSB pin level **at power-up reset**:
- **CSB = HIGH (V_DDIO) → I²C mode**
- CSB = LOW or transient toggle → SPI mode locked in (until next POR)

**v7.2 / porting-doc do not call out the CSB pin disposition.** If left floating or routed to an ESP GPIO that happens to read LOW during BME688 power-up, the chip will lock into SPI mode and stay deaf to I²C until next power-cycle. **Action:** confirm v7.2 schematic ties CSB directly to V_DDIO (3V3) at the chip. Datasheet [p. 52, Picture 15(a)] shows the I²C connection diagram explicitly with CSB→V_DDIO.

### 2. SDO pin cannot float [p. 45]

SDO selects the I²C address LSB:
- **SDO = GND → address 0x76 (default)**
- SDO = V_DDIO → address 0x77 (clash with BMP280)

*"The SDO pin cannot be left floating; if left floating, the I²C address will be undefined."* [p. 45]

v7.2 / porting-doc say address = 0x76. **Action:** confirm SDO is tied to GND on PCB.

### 3. No interrupt pin [p. 51, Table 26]

BME688 has **no INT pin**. There is no `new_data` interrupt output. The only way to know a measurement is complete is to poll the `meas_status` register (0x1D/0x2E/0x3F bit 7 = new_data). The porting-doc line 31 *"INT — not routed"* — confirmed; there's no INT signal anywhere on the chip. **All status sampling is polled.**

This makes the 200 ms forced-mode cycle even more interesting: the FW *must* poll repeatedly during that window (or trust the meas-dur computation and sleep blindly). The Bosch BME68x library uses the latter approach — `bme68x_get_meas_dur()` returns a μs estimate; FW calls `delay()` for that long, then issues a single read.

### Firmware-critical bit fields

**ctrl_hum (0x72)** [p. 35, 36]
- `[6] spi_3w_int_en` — Enable new-data interrupt on SDO pad in SPI 3-wire mode only (not used in I²C)
- `[2:0] osrs_h[2:0]` — Humidity oversampling: 000 = skipped, 001 = 1×, 010 = 2×, 011 = 4×, 100 = 8×, 101 (and others) = 16×

**ctrl_meas (0x74)** [p. 35, 36, 37]
- `[7:5] osrs_t[2:0]` — Temperature oversampling (same codes as osrs_h)
- `[4:2] osrs_p[2:0]` — Pressure oversampling (same codes as osrs_h)
- `[1:0] mode[1:0]` — **00 = Sleep, 01 = Forced, 10 = Parallel, 11 = reserved** [p. 17 Table 12]

**config (0x75)** [p. 37]
- `[4:2] filter[2:0]` — IIR filter coefficient: 000=0 (off), 001=1, 010=3, 011=7, 100=15, 101=31, 110=63, 111=127. Applies to temperature and pressure only — humidity and gas bypass the filter.
- `[0] spi_3w_en` — Enable SPI 3-wire mode (ignore in I²C)

**ctrl_gas_0 (0x70)** [p. 39]
- `[3] heat_off` — 1 = turn off heater current (manual override)

**ctrl_gas_1 (0x71)** [p. 39, 40]
- `[5] run_gas` — 1 = enable gas conversion
- `[3:0] nb_conv[3:0]` —
  - In **forced mode**: index of the heater step to use (0–9)
  - In **parallel mode**: length of heater profile to execute (0000 = no conversion, 0001 = step 0 only, ..., 1001 = steps 0–8, 1010..1111 = steps 0–9 [p. 40])

**gas_wait_x (0x64–0x6D)** [p. 38, 39]
- `[5:0]` — timer base (1 ms/LSB, 0–63)
- `[7:6]` — multiplier (00 = ×1, 01 = ×4, 10 = ×16, 11 = ×64)
- Net range: 0–4032 ms.
- *"In practice, approximately 20–30 ms necessary for the heater to reach the intended target temperature."* [p. 28] — so `gas_wait_x` should be set to (settle_ms + measurement_ms), not just measurement_ms.

**meas_status_x (0x1D / 0x2E / 0x3F)** [p. 43, 44]
- `[7] new_data` — 1 = data field has fresh data not yet read by host. **Clears when the data registers are read.**
- `[6] gas_measuring` — 1 during the gas heater + ADC phase
- `[5] measuring` — 1 during the overall TPHG conversion (set/cleared by chip)
- `[3:0] gas_meas_index` — Which heater step's data this field holds (parallel mode)

**gas_r_lsb_x (0x2D / 0x3E / 0x4F)** [p. 43, 44]
- `[7:6] gas_r[1:0]` — Two LSBs of 10-bit gas-resistance raw ADC value (high 8 bits live in gas_r_msb_x)
- `[5] gas_valid_r` — 1 = ADC conversion was a real one (not a dummy in parallel mode)
- `[4] heat_stab_r` — 1 = heater reached and held target temperature during this slot
- `[3:0] gas_range_r` — ADC range used (for resistance compensation)

## Initialization sequence (Forced mode) [p. 19, Figure 3]

```
1. After POR (t_startup = 2 ms once V_DD > 1.58 V and V_DDIO > 0.65 V) [p. 7].
2. (Optional) Soft-reset: write 0xB6 to 0xE0. Wait ~5 ms.
3. Verify chip_id at 0xD0 reads 0x61.
4. Verify variant_id at 0xF0 reads 0x01 (BME688, not BME680).
5. Read calibration registers (par_t1..3, par_p1..10, par_h1..7, par_g1..3,
   res_heat_range, res_heat_val) — Bosch lib does this once.
6. Set oversampling. WRITE 0x72 (ctrl_hum) FIRST [p. 19]:
     0x72 = osrs_h        (recommend 0b001 = 1×)
   Then 0x74 (ctrl_meas), leaving mode = 00 (sleep):
     0x74 = (osrs_t << 5) | (osrs_p << 2) | 0b00
   (recommend osrs_t = 010 = 2×, osrs_p = 101 = 16× per Bosch quick-start [p. 19])
7. Set IIR filter (config 0x75):
     0x75 = (filter << 2) | 0  (filter = 000 = off for forced mode)
8. Enable gas: ctrl_gas_1 (0x71) =
     run_gas = 1 (bit 5), nb_conv = heater_step_index (e.g. 0)
     -> 0x20 | 0x00 = 0x20
9. Program heater step 0:
   a. Convert target_temp (320 °C) and current ambient (e.g. 25 °C) to res_heat_x
      using the formula on [p. 27] — Bosch lib does this via bme68x_set_heatr_conf().
   b. Write res_heat_0 (0x5A) = computed code.
   c. Compute gas_wait_0 = (heater_settle_ms + measurement_ms). For 150 ms hold:
      gas_wait_0 = 0x80 | 59  (multiplier ×4, timer 59 ≈ 236 ms ... or use ×1 / 150).
      Bosch lib formats this in bme68x_set_heatr_conf() too.
   d. (Optional) Write idac_heat_0 to seed heater current and speed up plateau.
10. Read sensor temperature (ambient) and update amb_temp in the Bosch dev struct
    so the next res_heat conversion uses the correct ambient.
11. Trigger forced cycle: write mode = 01 to ctrl_meas (0x74) preserving osrs bits.
12. Wait `bme68x_get_meas_dur() + gas_wait_0` µs (~190 ms for 1×OSR + 150 ms heater).
13. Poll meas_status_0 (0x1D) bit 7 (new_data) — if 0, wait and retry.
14. Burst-read 17 bytes from 0x1F (press_msb_0) through 0x2F (sub_meas_index_1)
    — actually read 0x1F..0x2D (15 bytes), or use the standard Bosch lib helper.
15. Check gas_valid_r (gas_r_lsb_0 bit 5) and heat_stab_r (bit 4). Both must be 1
    for `gas_valid` to be set.
16. Pass raw data to Bosch lib for compensation:
    bme68x_get_data() returns compensated T (°C), P (Pa), H (%rH), gas_R (Ω).
17. Chip auto-returns to sleep mode after forced cycle. [p. 17]
```

**Timing summary [p. 7, 8, 28]:**
- t_startup (power-up to first I²C): 2 ms
- Soft-reset: write 0xB6 takes effect immediately; allow 5 ms for full settle
- Heater settle: 20–30 ms
- Heater hold: programmable 0–4032 ms
- TPH measurement: depends on OSR (1 ms typ at 1×; ~20 ms at 16×)
- Total forced-mode cycle (1× OSR T/P/H + 150 ms heater): **~190 ms**

## Operation

### Sensor modes [p. 17 Table 12]

| mode<1:0> | Mode | Key features |
|---|---|---|
| 00 | Sleep | No measurements. Min power (~0.15 µA typ). Chip auto-enters after each forced cycle. |
| 01 | Forced | Single TPHG cycle, then auto-return to sleep. **Used by Mk I.** |
| 10 | Parallel | TPH measured in parallel with gas heater across up to 10 steps. Sensor stays in parallel mode until host writes a different mode. |
| 11 | reserved | — |

### Forced mode detail [p. 17, Figure 2]

In forced mode, one cycle = T → P → H → Heater (G0). When host writes mode = 01:
1. Chip starts TPH measurement immediately.
2. Heater starts after TPH completes (sequential).
3. Gas resistance measured at end of heater pulse.
4. Data lands in Field 0 (registers 0x1D–0x2D).
5. Chip enters sleep mode.

Re-triggering: write mode = 01 again. **Further mode-change commands are ignored until the current cycle finishes.** [p. 17]

### Parallel mode detail [p. 17, 19, 21, 22]

In parallel mode, TPH and gas heater run concurrently across up to 10 heater steps. The 3 data fields (0, 1, 2) are filled cyclically. If nb_conv > 3, older fields are overwritten — host must drain in time.

**Not used in Mk I Phase 3** but supported by the Bosch lib.

### Gas heater operation [p. 27, 28]

The metal-oxide heater is controlled by a closed-loop current source:
- **idac_heat_x (0x50–0x59)** — optional initial current seed
- **res_heat_x (0x5A–0x63)** — target resistance code (encodes target temp; computed via the equation on [p. 27] using par_g1, par_g2, par_g3, res_heat_range, res_heat_val and the user's target temperature + ambient)
- **gas_wait_x (0x64–0x6D)** — heat-on duration

For a single forced-mode cycle the FW writes step 0 (res_heat_0, gas_wait_0) and selects it via `nb_conv = 0` in ctrl_gas_1.

**Power consumption of heater:** 9 / 12 / 13 mA min/typ/max at 320 °C continuous, 15–18 mA peak in first 1 ms of pulse [p. 8].

### I²C bus contention impact

With heater hold = 150 ms and TPH at 1× OSR (~10 ms), one forced-mode cycle takes ~190 ms. The current driver holds the I²C bus 1 mutex for the entire duration [porting-doc DEFECT-002, HIGH]. With a 2 s poll, that's a **10 % bus-blocking duty cycle on Bus 1** — confirmed against the Sim 1 number in the kickoff doc.

**Mitigation paths for FW:** split the mutex into three acquisitions (trigger / wait-without-mutex / read). Datasheet supports this: the chip auto-runs the heater in the background, and the data registers do not change during the wait. **Risk:** the Bosch lib is stateful and was not designed for mid-cycle re-entrancy. Either:
- Call bme68x_set_op_mode() to trigger, release mutex, vTaskDelay(meas_dur_us / 1000), re-acquire mutex, call bme68x_get_data().
- Or use parallel mode with a 3-second window and read all 3 fields in a single mutex acquisition every poll cycle.

### Polling for completion

Without an INT pin, completion must be polled:
- **Trust meas_dur:** simplest — sleep for the duration returned by `bme68x_get_meas_dur()` plus heater-on time, then read once.
- **Active poll:** read meas_status_0 (0x1D) every ~10 ms until new_data bit 7 = 1. More bus traffic but more robust against unknown delays.

The Bosch lib uses the trust-meas-dur approach.

### Compensation formulas

Datasheet provides full floating-point and integer reference C code for compensation [p. 23–29]:
- Temperature: `temp_comp = t_fine / 5120.0` (°C), where `t_fine` is the fine resolution intermediate
- Pressure: 18-equation polynomial using par_p1..par_p10 (Pascals)
- Humidity: uses temp_comp + 7 humidity calib params (% relative humidity)
- Gas resistance: `gas_res = 1000000 / ((((262144 >> gas_range) − 512) × 3 × 4096 + gas_adc)) × calib_factor` — see [p. 28] for exact equation. (Ohms.)

**Use the Bosch sensor API** (boschsensortec/bme68x_sensor_api). The porting doc already pulls v4.4.8 as a managed component.

### IIR filter for T and P [p. 26, 27, 37]

When enabled, the IIR filter smooths temperature and pressure:
- `x_filt[n] = (x_filt[n-1] × (c − 1) + x_adc) / c`
- Coefficients 0 / 1 / 3 / 7 / 15 / 31 / 63 / 127
- **Humidity and gas bypass the filter.**
- Resolution increases to 20 bits with filter on (vs 16 + osrs−1 bits with filter off).
- Useful for parallel mode at 1 Hz+. For our 2 s forced cycle, filter is off (porting doc confirms).

### BSEC vs raw

Bosch BSEC (Bosch Software Environmental Cluster) is the closed-source library that turns raw gas resistance into IAQ (0–500), CO₂ equivalent (ppm), bVOC equivalent (ppm), and a stable temperature/humidity (after compensating for self-heating). Mk I uses **raw gas resistance only**; BSEC integration is deferred to v2 per the porting doc.

BSEC modes [p. 30 Table 19]:
| Mode | Update rate | Avg current |
|---|---|---|
| Gas Scan (scan) | 1/10.8 s | 3.96 mA |
| Ultra-low power (ULP) | 3.3 mHz (one read per 5 min) | 0.09 mA |
| Quick Ultra-low power (q-ULP) | 0.33 Hz T/P/H / 3.3 mHz IAQ | 0.1 mA |
| Low power (LP) | 0.33 Hz | 0.9 mA |
| Continuous | 1 Hz | 12 mA |

The Mk I 0.5 Hz forced-mode cycle (150 ms heater @ 12 mA → ~1 mA average) sits between LP and q-ULP, consistent with the porting doc's "~1 mA average".

## Ranges / Sensitivity

### Operating range [p. 3, 8]
- Temperature: −40 to +85 °C operational; full accuracy 0–65 °C
- Pressure: 300–1100 hPa
- Humidity: 0–100 % rH (non-condensing); full accuracy 10–90 % at 0–65 °C
- Supply: V_DD 1.71–3.6 V, V_DDIO 1.2–3.6 V

### Sensor accuracy (typ)
- **Temperature** (T_A 0–65 °C) [p. 14]: ±0.5 °C absolute; resolution 0.01 °C; noise 0.005 °C RMS
- **Pressure** (T_A 0–65 °C, P 300–1100 hPa) [p. 13]: ±0.6 hPa absolute, ±0.12 hPa relative; resolution 0.18 Pa; noise 1.4 Pa RMS at full BW / 0.2 Pa at reduced BW
- **Humidity** (T_A 25 °C, 20–80 %rH) [p. 12]: ±3 % rH absolute; hysteresis ±1.5 %; nonlinearity 1.7 %; response time τ_63 % ≈ 8 s; resolution 0.008 %; noise 0.01 % RMS
- **Gas resistance** [p. 8]: resolution 0.05–0.11 % of range; noise 1.5 % RMS; range/resolution depend on gas_range_r setting

### Oversampling values [p. 36]
osrs_x[2:0]: 000 = skipped (0x8000 output), 001 = 1×, 010 = 2×, 011 = 4×, 100 = 8×, 101 and others = 16×

## Interrupts

**The BME688 has no INT pin.** The chip has no electrical interrupt output to the host.

The only completion-status path is to **poll `meas_status_x` (0x1D / 0x2E / 0x3F) bit 7 (`new_data`)** until it reads 1. Reading the data registers (e.g., 0x1F–0x2D) clears `new_data`.

There is a `new_data` interrupt available *only* on the SDO pad in SPI 3-wire mode (enabled by `spi_3w_int_en` = 1 in ctrl_hum[6] — irrelevant in I²C [p. 35]).

**Mk I has no choice but to poll.** Either:
- Trust `bme68x_get_meas_dur()` + heater wait, sleep blindly for that duration, then read.
- Or actively poll meas_status_0 every ~10 ms during the wait.

### Calculation for Mk I configuration

- Heater on: 150 ms × 12 mA = 1.8 mC charge per cycle
- TPH measurement: ~10 ms × ~1 mA = 10 µC

## Datasheet notes

- **t_startup is gated by BOTH V_DD > 1.58 V and V_DDIO > 0.65 V** [p. 7]. If one ramps slower than the other (different LDOs), the chip waits for the slower rail. Mk I uses a single 3V3 rail for both → not an issue.
- **The chip is optimized for 1.8 V V_DD per Footnote 1 [p. 7].** Higher V_DD (e.g. 3V3) works but is less power-efficient. Bosch's current-consumption figures assume 1.8 V. Real Mk I current at 3V3 may be slightly higher.
- **PSRR is ±0.01 %rH/V / ±5 Pa/V over full V_DD range** [p. 7]. At 3V3 supply with 50 mV ripple max, sensor reads are stable.
- **Status registers latch the gas_valid_r and heat_stab_r bits per field.** If the FW reads a field whose new_data = 0, the data is whatever was last latched there — could be from a previous cycle. **Always check new_data BEFORE consuming data.** Bosch lib does this.
- **No internal calibration of the IIR filter** when measurements are skipped — if osrs_t = 0 mid-stream and later re-enabled, the first sample after re-enable is filtered with stale history. Write to `filter` register to reset history. [p. 27]
- **Soft-reset (0xB6 to 0xE0) is preferred over power-cycle** for clean state. Resets all registers and re-runs the start-up sequence (2 ms).
- **Variant_id distinguishes BME680 (0x00) from BME688 (0x01).** chip_id 0x61 alone is ambiguous. The porting doc's `bme68x_init` chip-id probe is correct as far as it goes, but adding a variant_id check (recommended) catches a BME680 substitution which would not support the AI gas-scanner features.
- **Engineering samples** may not have a flashed variant_id [p. 55] — the BME68x lib needs manual config for those. Production parts ("CCCT" or "CCC TL" mark) always have variant_id = 0x01.
- **No clock stretching support on SCL** [p. 45] — the bus master is in full control of timing. If the ESP-IDF I²C driver tries to honor clock stretching from this chip, it will see a high-Z line and read what's effectively garbage. Set `clk_stretch_tick` to 0 or default; do not enable stretching.
- **Solder height ≥ 50 µm** required to mechanically decouple from PCB stress [p. 13 footnote 17, p. 56]. Solder paste height affects long-term pressure offset.
- **Vent hole must remain unblocked** by conformal coating, glue, or housing — it's the gas inlet.
- **Calibration parameters live across non-contiguous addresses** — Bosch lib reads them in chunks. Don't try to do a single burst read across 0x00..0xEE.
- **For BSEC integration**, the BSEC binary is a closed-source library — license required from Bosch website. Mk I defers this to v2; raw gas resistance is exposed and the fusion layer can compute its own VOC index.

## Warnings & Errata

| ID | Title | Impact | Notes |
|---|---|---|---|
| WARN-01 | CSB pin disposition not specified in v7.2 | HIGH | [p. 45, 46, 52]. CSB must be tied directly to V_DDIO for I²C mode at every power-up. If routed to a floating GPIO, the chip locks into SPI mode and is unreachable via I²C. Mitigation: confirm v7.2 schematic ties CSB → V_DDIO directly. |
| WARN-02 | SDO pin cannot float | HIGH | [p. 45]. Floating SDO → undefined I²C address. Mitigation: confirm SDO tied to GND (for 0x76). |
| WARN-03 | No INT pin — polled operation only | MED | [p. 51]. FW must trust `bme68x_get_meas_dur()` or actively poll meas_status. The Bosch lib's approach (trust meas_dur) is standard and matches Mk I porting choice. |
| WARN-04 | Mutex held for full ~190 ms forced cycle | MED | porting-doc DEFECT-002. Bus 1 unavailable to touch/sensors for 10 % of every 2 s. **The chip itself does not require the mutex during the heater hold** — the I²C bus is idle for that whole period. FW could release the mutex. Risk: re-entering the Bosch lib mid-cycle is undefined behavior. Mitigation: refactor to split trigger / wait / read into three mutex acquisitions, or accept the 10 % blocking. |
| WARN-05 | gas_valid_r AND heat_stab_r required for gas validity | LOW | porting-doc DEFECT-003. On first 2–3 cycles after init, heat_stab_r may be 0 even with a healthy chip [p. 44]. Mitigation: log first-cycle gas_valid = false at boot and consider gating user-visible gas data on accuracy_status from BSEC if ever integrated. |
| WARN-06 | amb_temp seed at 25 °C affects first heater resistance code | LOW | porting-doc DEFECT-004. Bosch lib uses amb_temp in the res_heat conversion formula [p. 27]. If the watch is bring-up'd at e.g. 0 °C with amb_temp = 25 °C, the heater code is slightly off and the first gas reading is biased. Self-corrects after one cycle. |
| WARN-07 | Engineering samples lack variant_id | LOW | [p. 55]. Marked with "*", "e", or "E". The BME68x lib expects variant_id = 0x01; on engineering samples it must be manually set. Production parts unaffected. |
| WARN-08 | Clock stretching NOT supported | LOW | [p. 45]. ESP-IDF I²C driver default does not enable stretching, so this is informational. Confirm no special "clock-stretch enable" flag is set. |
| WARN-09 | Up to 10 heater steps; nb_conv encoding differs Forced vs Parallel | LOW | [p. 40]. In forced mode, nb_conv = step index (0..9). In parallel mode, nb_conv = profile length (0..15 with 10..15 all meaning 9 steps). If FW switches between modes, nb_conv must be re-computed. Bosch lib handles this. |
| WARN-10 | Calibration coefficients scattered across address space | LOW | [p. 23–28]. Bosch lib reads them correctly. If anyone writes a from-scratch I²C driver, ensure all coefficients are picked up — missing par_h coefficients in particular produce nonsense humidity. |
| WARN-11 | Vent hole orientation matters for response time | LOW | [p. 12 footnote 16]. ~1 m/s air-flow recommended. Wrist enclosure design must not seal the vent. |
| WARN-12 | Long-term drift 0.012/year | LOW | [p. 10]. Acceptable for wearable. BSEC's auto-trim compensates if/when integrated. |

## Open questions

1. **CSB / SDO PCB net check.** Both pins have pinout-disposition gaps in v7.2. **Action:** Ivan / hardware review of v7.2 schematic to confirm CSB→V_DDIO and SDO→GND.
2. **Mutex split for 190 ms forced cycle.** Worth the refactor risk on the Bosch lib re-entry? **Recommend:** measure bus contention impact on bench first; refactor only if touch latency becomes a problem.
3. **Active poll vs trust meas_dur.** Bosch lib uses trust-meas-dur. Robust enough for Mk I? **Recommend:** keep trust-meas-dur (matches Bosch lib design); add a watchdog read 2× meas_dur out as a safety net.
4. **Variant ID check in FW.** Currently the Bosch lib `bme68x_init` only checks chip_id. **Recommend:** read variant_id at init too, log it, refuse to proceed if value isn't 0x01 (catches BME680 substitution at factory).
5. **Heater profile tuning.** 320 °C / 150 ms is the Bosch "VOC sniffing" default. Per AN001, the right answer depends on the target VOC mix. Mk I has no specific gas target — recommend ship default and revisit if/when BSEC arrives.
6. **BSEC integration timeline.** Closed-source binary, requires Bosch SLA. Mk I deferred per porting doc. **Action:** decide whether v2 ships with BSEC IAQ or just raw gas resistance.
7. **Power budget at 3V3.** Bosch's current figures assume 1.8 V V_DD. At 3V3, expect ~1.5× the average current (~1.3 mA instead of 0.9 mA). **Recommend:** measure on bench; if power-budget critical, add 1.8 V LDO between V_DD and the buck — same LDO that should already be on the MAX30101 V_DD pin per 20.11.
