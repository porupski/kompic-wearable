# 20.10b — LSM6DSV16X ADVANCED FEATURES (MLC / FSM / SFLP / Qvar / Sensor Hub / Embedded Functions)
**Date:** 2026-06-13 · **Datasheet:** `lsm6dsv16x.pdf` (STMicroelectronics DS13510, Rev. 4, May 2023) · **Pages:** 198 total · **Hardware:** iv7.1 · **Firmware porting:** f0.0
**Parsed by:** Claude Code Opus
**Scope:** Companion to **20.10** (which covers accel/gyro/INT1/power). This file documents the LSM6DSV16X's **on-chip "edge intelligence"** features — embedded functions, FSM, MLC, Adaptive Self-Configuration, Sensor Fusion Low-Power (SFLP), Qvar electrostatic sensing, Analog Hub, and Sensor Hub (Mode 2 I²C master).
**v7.2 baseline:** these features are **opt-in** — none required for basic IMU operation. Each section identifies which are *recommended* to enable for wearable use, which are *useful for future iterations*, and which are *out of scope* for v7.2.

## 0. Foundational: Bank switching

All "embedded functions" (pedometer, tilt, SMD, FSM, MLC, ASC, SFLP) live in a **separate register bank** at addresses 0x00–0x7F that is **shadowed onto the main register space when an access bit is set**.

```
9.1 FUNC_CFG_ACCESS (0x01)         [p. 56 §9.1]
   [7]  EMB_FUNC_REG_ACCESS  → 1 = embedded functions bank exposed
   [6]  SHUB_REG_ACCESS      → 1 = sensor hub bank exposed
   [3]  FSM_WR_CTRL_EN       → 1 = FSM can write to main CTRL regs
   [2]  SW_POR               → 1 = global device reset (auto-clears)
   [1]  SPI2_RESET           → 1 = reset SPI2 primary regs (manual clear)
   [0]  OIS_CTRL_FROM_UI     → 1 = OIS chain controlled from primary interface
```

**Critical FW pattern** — wrap all embedded-function access:

```python
def embedded_write(reg, value):
    i2c_write(0x6B, 0x01, 0x80)       # enter embedded bank
    i2c_write(0x6B, reg, value)
    i2c_write(0x6B, 0x01, 0x00)       # exit back to main bank

def sensorhub_write(reg, value):
    i2c_write(0x6B, 0x01, 0x40)       # enter sensor-hub bank
    i2c_write(0x6B, reg, value)
    i2c_write(0x6B, 0x01, 0x00)       # exit
```

**Forgetting to switch back** is the #1 advanced-feature bug. Symptom: subsequent CTRL1/CTRL8 writes silently land in the embedded bank instead of the main IMU bank — accel doesn't respond, gyro doesn't respond, debugging takes hours. Wrap it all in helpers. See WARN-01 below.

**Aggregate status overview** in the main bank:
```
0x1D   ALL_INT_SRC      [p. 76 §9.27]
   [6] EMB_FUNC_IA   embedded functions event (pedometer/tilt/SMD/FSM/MLC)
   [5] SHUB_IA       sensor hub
   [4] SLEEP_CHANGE_IA  activity/inactivity change
   [3] D6D_IA        6D orientation change
   [1] TAP_IA        tap event
   [1] WU_IA         wake-up
   [0] FF_IA         free-fall
```

A single read of `ALL_INT_SRC` tells you which subsystem fired — then read the relevant per-subsystem SRC register to clear and detail the event.

## 1. Pedometer (step counter + step detector)

**What it does** [p. 4–5 §2.1, §2.2]: counts user's steps using a dedicated 30 Hz pipeline that runs **independent of the main accel ODR** — meaning the pedometer keeps counting even when the host has the accel in low-power 1.875 Hz mode for screen-off battery saving.

**Algorithm** (4 stages, p. 5):
1. `|V|` — compute the magnitude of the 3-axis acceleration (orientation-agnostic).
2. FIR low-pass filter — smooths high-frequency components.
3. Peak detector — finds local max/min.
4. Threshold/step update — counts step if peak-to-peak exceeds adaptive threshold, with debounce for false walks.

**Output:** 16-bit unsigned step count (resets on enable cycle). Step-detected event can be routed to INT pin or batched into FIFO.

**Enable steps:**
1. Set accel to a continuous mode (any ODR ≥ 30 Hz; LP mode 1 @ 30 Hz works).
2. `bank_switch(EMBED)` → write `EMB_FUNC_EN_A` to enable PEDO_EN bit.
3. (Optional) configure debounce / threshold via `PEDO_CMD_REG`.
4. (Optional) enable INT1 routing: bank-main → `MD1_CFG.INT1_STEP_DETECTOR = 1`.
5. Read step counter from `STEP_COUNTER_L/H` (embedded bank).

**Power cost:** "negligible" per datasheet [p. 4 §2.1] — added current is dominated by the accel itself (~10 µA in LP mode 1). The pedometer logic itself is sub-µA.

**False-positive rejection** [p. 5]: the algorithm has a minimum-steps-before-counting filter to reject false walks (e.g., wrist swing while typing). Configurable.

**v7.2 recommendation: ENABLE.** Industry-standard wearable feature. Add to FW boot config.

## 2. Tilt detection

**What it does** [p. 5 §2.3]: hardware-based detection of a **change in device tilt**, e.g., user goes from sitting (phone in pocket pointing down) to standing (phone in pocket pointing forward). Accelerometer-only (no gyro) for ultra-low power.

**Triggers when:** tilt changes meaningfully. Specifically does **not** trigger while user is walking/running/climbing stairs (those produce continuous tilt variation that the algorithm filters out).

**Output:** single interrupt event when tilt-change detected. Status bit `IS_TILT` in `EMB_FUNC_STATUS_MAINPAGE` (0x49) [p. 89 §9.49].

**Use case for v7.2:** wrist-context awareness — "user lifted hand" → could complement the wrist-raise wake gesture (but wake-up + 6D is the more standard approach).

**v7.2 recommendation: OPTIONAL.** Lightweight, but the wake-up + 6D combo covers the same UX surface.

## 3. Significant Motion Detection (SMD)

**What it does** [p. 5 §2.4]: generates a single interrupt when the user has done a "significant motion" — interpreted as a change in user location (walked from one room to another).

**Trigger logic:** integrates motion magnitude over a window; fires when the accumulated motion exceeds a threshold. Accel-only.

**Status bit:** `IS_SIGMOT` in `EMB_FUNC_STATUS_MAINPAGE` (0x49) [p. 89 §9.49].

**Use case for v7.2:** detect "user has moved" → could prompt re-localization (re-fetch weather, re-check pedometer baseline), or wake from a deep "asleep on desk" state.

**v7.2 recommendation: OPTIONAL.** Useful as a low-power "context changed" trigger, but not core UX.

---

## 4. 6D / 4D Orientation detection

**What it does** [p. 86–87 §9.47 D6D_SRC]: detects which of the 6 device orientations is currently active (portrait/landscape, face-up/face-down). Edge-triggered on changes.

**Source register `D6D_SRC` (0x47):**
```
[6] D6D_IA   1 = orientation change detected
[5] ZH       Z-axis high (face-up)
[4] ZL       Z-axis low (face-down)
[3] YH       Y-axis high (landscape-right)
[2] YL       Y-axis low (landscape-left)
[1] XH       X-axis high (portrait-up)
[0] XL       X-axis low (portrait-down)
```

**Configuration:** threshold + duration in `THS_6D` register (sin(α) lookup); also TAP_CFG0.LOW_PASS_ON_6D selects filter source.

**Use case for v7.2:** auto-rotate screen (portrait vs landscape) — minor for a circular watchface, but useful for things like "wrist facing user" (face-up gating wake gesture).

**v7.2 recommendation: OPTIONAL.** Pairs well with wrist-raise wake for false-trigger rejection.

## 5. Wake-up + Single-tap + Double-tap

### Wake-up [p. 86 §9.45 WAKE_UP_SRC]

**Trigger:** any axis acceleration exceeds threshold for N consecutive samples.

**Configuration:**
- `WAKE_UP_THS (0x5B)` — threshold in mg, weighting from INACTIVITY_DUR.WU_INACT_THS_W
- `WAKE_UP_DUR (0x5C)` — sleep duration, wake event duration
- `INACTIVITY_DUR (0x54)` — threshold weight, post-event ODR (1.875 / 15 / 30 / 60 Hz)
- `INACTIVITY_THS (0x55)` — activity threshold (6-bit unsigned)
- `FUNCTIONS_ENABLE (0x50).INTERRUPTS_ENABLE = 1` — enable basic interrupts
- `MD1_CFG (0x5E).INT1_WU = 1` — route to INT1

**Per-axis source bits** in `WAKE_UP_SRC (0x45)`:
```
[5] SLEEP_CHANGE_IA   sleep/activity transition
[4] FF_IA             free-fall event
[3] SLEEP_STATE       0 = active, 1 = inactive (sleep state)
[2] WU_IA             wake-up event fired
[2] X_WU              ↳ on X-axis
[1] Y_WU              ↳ on Y-axis
[0] Z_WU              ↳ on Z-axis
```

**Reading WAKE_UP_SRC clears the latched event** (if LIR=1 in TAP_CFG0).

### Tap / Double-tap [p. 87 §9.46 TAP_SRC, p. 94 §9.57 TAP_CFG0]

**Trigger:** sharp acceleration spike on enabled axis (X/Y/Z) exceeding tap threshold within a quiet window.

**Configuration:**
- `TAP_CFG0..2` — axis enables (TAP_X_EN, TAP_Y_EN, TAP_Z_EN), latch mode (LIR), HP filter selection
- `TAP_THS_6D` — threshold (same register holds 6D threshold)
- `INT_DUR2` — quiet/shock/duration timing for double-tap
- `WAKE_UP_THS.SINGLE_DOUBLE_TAP` — choose single-only or single+double mode

**Source bits in `TAP_SRC (0x46)`:**
```
[6] TAP_IA        tap event
[5] SINGLE_TAP    single-tap (only if SINGLE_DOUBLE_TAP allows)
[4] DOUBLE_TAP    double-tap
[3] TAP_SIGN      0 = positive accel, 1 = negative
[2] X_TAP         tap on X
[1] Y_TAP         tap on Y
[0] Z_TAP         tap on Z
```

**v7.2 recommendation:**
- **Wake-up: ENABLE** with X+Y enabled (wrist-raise = X and/or Y impulse). Threshold ~30–60 mg; tune on bench.
- **Single-tap: OPTIONAL** (UX gesture: tap watchface to wake display).
- **Double-tap: OPTIONAL** (UX gesture: double-tap to dismiss notification).
- Use on Z-axis for "tap front of watch."

## 6. Free-fall

**What it does:** detects when all 3 axes simultaneously read below a threshold (= no support force = falling).

**Configuration:**
- `FREE_FALL (0x5D)` — threshold (FF_THS[2:0]) + duration low bits
- `WAKE_UP_DUR (0x5C).FF_DUR5` — duration high bits
- `FUNCTIONS_ENABLE.INTERRUPTS_ENABLE = 1`
- `MD1_CFG.INT1_FF = 1` to route to INT1

**Source bit:** `FF_IA` in `WAKE_UP_SRC (0x45)` and aggregated in `ALL_INT_SRC.FF_IA`.

**Threshold options (FF_THS[2:0]):** typical thresholds 156 mg, 219 mg, 250 mg, 312 mg, 344 mg, 406 mg, 469 mg, 500 mg (consult Table in §9 free-fall section of datasheet for exact values).

**Use case:** "watch fell off wrist" alert + auto-lock; or activity-tracker "user dropped phone."

**v7.2 recommendation: OPTIONAL.** Easy to enable; tune threshold and duration per UX. Low cost.

## 7. Activity / Inactivity (auto-sleep)

**The killer power-management feature** [p. 91 §9.53 FUNCTIONS_ENABLE; p. 93 §9.55 INACTIVITY_DUR].

**What it does:** the chip itself automatically transitions accel to low-power mode 1 (and optionally gyro to sleep or power-down) when no motion is detected, and back to full operation when motion resumes — **all without host intervention**.

**Configuration `FUNCTIONS_ENABLE (0x50).INACT_EN[1:0]`** [p. 91]:
```
00 = stationary/motion-only interrupts (no automatic mode change)
01 = inactivity → accel → LP mode 1 at INACTIVITY_DUR.XL_INACT_ODR; gyro unchanged
10 = inactivity → accel → LP mode 1; gyro → SLEEP mode (warm, fast wake)
11 = inactivity → accel → LP mode 1; gyro → POWER-DOWN (slow wake, lowest power)
```

**Configuration `INACTIVITY_DUR (0x54)`:**
- `WU_INACT_THS_W[2:0]` — weight per LSB of threshold: 7.8125 / 15.625 / 31.25 / 62.5 / 125 / 250 mg per LSB
- `XL_INACT_ODR[1:0]` — accel ODR during inactivity: 1.875 / 15 / 30 / 60 Hz
- `INACT_DUR[1:0]` — wake-back-up duration: 1 / 2 / 3 / 4 consecutive over-threshold events

**Threshold** in `INACTIVITY_THS (0x55)` — 6-bit unsigned, multiplied by weight.

**Status:** `SLEEP_STATE` bit in `WAKE_UP_SRC` + `SLEEP_CHANGE_IA` in `ALL_INT_SRC`. Route to INT via `MD1_CFG.INT1_SLEEP_CHANGE = 1`.

**v7.2 recommendation: ENABLE with INACT_EN = 10 (LP accel + gyro sleep)**:
- During wrist-still phases (user typing, sleeping, holding still): chip auto-drops accel to 15 Hz LP mode 1 (~10 µA) and gyro to sleep (warm, ready to wake fast).
- On motion: chip auto-restores prior accel ODR and gyro to operational mode within ~1 ms.
- Saves several mA-hours per day vs always-on combo HP. Host doesn't need to manage power state.
- Default threshold tuning: ~62.5 mg × 4 LSB ≈ 250 mg threshold, INACT_DUR = 2 events.

## 8. Finite State Machine (FSM)

**What it is** [p. 6 §2.5]: **8 independent user-programmable state machines** that execute on incoming sensor data (accel + gyro + optional external mag via Sensor Hub) and generate interrupts when programmed gesture patterns match.

**Programming model:**
- Each FSM is a flowchart of states, transitions, conditions on sensor inputs.
- States are loaded as **bytecode** into the FSM RAM (configurable size, max 16 KB total across all 8 FSMs and MLC).
- Programmed using **ST's MEMS Studio** (or legacy "Unico GUI") — drag-and-drop state design + condition editor.
- AN5882 is the official application note.

**Use cases:** glance gesture, absolute wrist tilt, shake, double-shake, swipe, "wave to dismiss", boxing-punch, golf-swing, etc.

**Outputs:**
- `IS_FSM1..IS_FSM8` bits in `FSM_STATUS_MAINPAGE (0x4A)` [p. 89 §9.50]
- Route any subset to INT1 via `MD1_CFG` (FSM-specific bits) and the embedded function INT routing
- Long-counter timeout: `IS_FSM_LC` bit in `EMB_FUNC_STATUS_MAINPAGE (0x49)`

**v7.2 strategy:**
- **DEFER for v0** — FSM programming is a serious effort (days of work per gesture). Get baseline wake+tap+pedometer working first.
- **For v1+**: prioritize "glance to wake" (FSM watches for the wrist-rotate-toward-face pattern that wake-up alone misses), "shake to dismiss," and "double-knock to pair."

## 9. Machine Learning Core (MLC)

**What it is** [p. 7 §2.6]: **4 independent decision-tree classifiers** running on accel + gyro (+ optional external sensors via Sensor Hub). Output: a class label per tree (0–255), updated at a configurable window rate.

**Pipeline (per tree)** [p. 7, Fig. 4]:
1. **Input sensors:** accel, gyro, ext mag/pressure (if Sensor Hub).
2. **Computation block:** runs configurable filters (HP/LP/IIR), computes "features" over a fixed time window (variance, energy, peak-to-peak, mean, min/max, zero-crossings, etc.).
3. **Decision tree:** trained off-chip (e.g., scikit-learn, then converted), evaluated on-chip. Up to **128 nodes total** across all 4 trees; each tree max 16 result classes; max 4 trees in parallel.
4. **Meta-classifier (optional):** smooths raw tree output via a filter window (e.g., "only declare 'running' if it's been 'running' for 5 consecutive windows").
5. **Result registers + INT** (on result change).

**Use cases:** activity recognition (walking/running/biking/stationary), fall detection, abnormal gait detection, custom gesture classification.

**Outputs:**
- `IS_MLC1..IS_MLC4` bits in `MLC_STATUS_MAINPAGE (0x4B)` [p. 90 §9.51] — interrupt when tree result changes
- Per-tree result value in `MLC1_SRC..MLC4_SRC` registers (embedded bank)

**Toolchain:** **ST MEMS Studio** + AN5804 (the official MLC application note). Train in Python/MATLAB, export `.ucf` config file, load into device at boot via the bank-switched `MLC*_INIT_VALUE` registers (or use ST's HAL function `lsm6dsv16x_mlc_set()`).

**v7.2 strategy:**
- **DEFER for v0** — needs training data + classifier design effort. Get baseline shipping first.
- **For v2+**: trained activity classifier (walking/running/cycling/stationary) running 24/7 in MLC = full fitness-tracking activity log with ~0 host CPU cost. Best ROI advanced feature for a wearable.

## 10. Adaptive Self-Configuration (ASC)

**What it is** [p. 7 §2.7]: a feedback loop where the **FSM can write to main control registers** (CTRL1-10) based on an MLC tree's output. Lets the device reconfigure itself in real time without host intervention.

**Example flow:**
1. MLC tree classifies activity as "running."
2. FSM observes the MLC result.
3. FSM issues `SETR` command (set register) to bump accel ODR from 30 Hz → 120 Hz for higher fidelity during running.
4. When MLC drops back to "stationary," FSM SETRs ODR back to 30 Hz.

**Enabling:**
- `FUNC_CFG_ACCESS.FSM_WR_CTRL_EN = 1` allows FSM to write to CTRL regs.
- `CTRL_STATUS (0x1A).FSM_WR_CTRL_STATUS` flag tells the host that FSM has the lock (host writes to CTRL regs are ignored).

**v7.2 strategy: DEFER.** Powerful but only useful once both FSM and MLC are programmed. v3+ if at all.

## 11. Sensor Fusion Low-Power (SFLP)

**What it is** [p. 8 §2.8 + Table 1]: **6-axis sensor fusion (accel + gyro)** running on-chip, producing:
1. **Game rotation vector** as a unit **quaternion** (X, Y, Z, W) — orientation in absolute space.
2. **Gravity vector** — 3D vector of gravity direction in device frame.
3. **Gyroscope bias** — current estimated gyro zero-rate bias (3D).

**Performance** [Table 1]:
| Condition | Heading/yaw | Pitch | Roll |
|---|---|---|---|
| Static accuracy | 0.5° / 5 min | 1.5° | 1.5° |
| Low dynamic | 0.7° / 5 min | 0.5° | 0.5° |
| High dynamic | 5.9° / 5 min | 1.6° | 1.2° |

Calibration time: 0.8 s. Orientation stabilization: 0.7 s.

**Output:** quaternion components are batched into the **FIFO** (X, Y, Z components stored — W is reconstructed by the host as `W = sqrt(1 - X² - Y² - Z²)`).

**Enabling:**
- `bank_switch(EMBED)` → `EMB_FUNC_EN_A (0x04).SFLP_GAME_EN = 1`
- (Reinit) `EMB_FUNC_INIT_A (0x66).SFLP_GAME_INIT = 1`
- Configure batching in `FIFO_CTRL3/4` (use SFLP-specific tags)

**Why it matters for v7.2:**
- Replaces the entire host-side Madgwick / Mahony filter — saves ~5–10% ESP CPU.
- Hardware-locked sample rate guarantees no aliasing (host-side fusion can drift if loop rate varies).
- Trade-off: less tunable than a software implementation; bias adaptation parameters are fixed.

**v7.2 recommendation: STRONGLY CONSIDER.** If the FW needs absolute orientation (compass heading + tilt + pitch — i.e., for any AR-like overlay, or accurate step-direction tracking), SFLP is the right tool. If only crude orientation is needed (just "is wrist face-up?"), 6D detection is cheaper.

## 12. Qvar (electrostatic / charge-variation sensing)

**What it is** [p. 8 §6.8 + Table 5 at p. 14]: an internal **electrostatic potential meter** that reads charge variation on two external electrodes (connected to pins 2 and 3 — `Qvar1` and `Qvar2`). Detects body touch, swipe, proximity (cm range) via the user's natural electrostatic field.

**Use cases per datasheet:**
- Tap on watch case (single, double, triple)
- Long press
- Left-swipe / right-swipe via touch electrode strip
- Generic proximity hover

**Electrical specs** [p. 14 Table 5]:
- Power consumption (Qvar enabled): **15 µA** extra (accel must be in HP or normal mode)
- Input impedance: configurable 235 MΩ to 2.4 GΩ (via `CTRL7.AH_QVAR_C_ZIN[1:0]`)
- Gain: 78 LSB/mV
- Input range: ±460 mV
- Noise (shorted inputs): 54 µV
- CMRR: 54 dB

**Data registers:** `AH_QVAR_OUT_L/H (0x3A–0x3B)` [p. 84 §9.42] — 16-bit signed, updated at 240 Hz typical.

**Enabling:**
- `CTRL7.AH_QVAR_EN = 1` — connects Qvar buffers to pins 2/3
- Accel must be in HP or normal mode (Qvar shares clock infrastructure with the analog hub)
- Note: when AH_QVAR_EN = 1, **SPI 3-/4-wire and analog-hub-master functionality on pins 2/3 are disabled** (Mode 1 only)

**Tap / swipe detection:** Qvar output is **routable as input to FSM and MLC** — so a "swipe detection" classifier can be programmed in MLC, just like accel-based gestures.

**v7.2 strategy: DEFER.**
- Requires **physical electrodes** on the watch case (typically conductive bezel ring or a hidden strip). v7.2 may not have these.
- If electrodes are present (or planned for v7.3): Qvar enables touch UX without a dedicated touch IC. Trade-off: more sensitive to EMI, requires shielding considerations.
- **Confirm with mechanical design** whether v7.1/v7.2 watch case includes electrodes. If yes — major UX feature. If no — defer.

## 13. Sensor Hub (Mode 2 — internal I²C master)

**What it is** [p. 10 Fig. 6]: when pin configuration is **Mode 2**, pins 2 and 3 become an **I²C master** (MSCL / MSDA) that the LSM6DSV16X uses to read up to **6 external sensors** (typically a magnetometer or pressure sensor) and merge their data into its own FIFO/output stream.

**Pin reassignments (Mode 2):**
- Pin 2 → MSDA (I²C master data)
- Pin 3 → MSCL (I²C master clock)
- Pin 9 → MDRDY (I²C master external sync)

**Why it exists:** lets the host see a single combined data stream (LSM6DSV16X output regs + sensor hub aux regs) instead of separately polling each sensor. Saves bus time and host CPU.

**v7.2 applicability: NONE.**
- v7.2 uses **Mode 1** (pins 2/3 = SDx/AH/Qvar1/2, tied to defined level or used for Qvar).
- The LIS3MDLTR [20.07] is connected to the **main bus 1**, not through the LSM's sensor hub.
- Switching to Mode 2 would require **rerouting the magnetometer to LSM's pins 2/3**, which is a major schematic change for marginal benefit.

**v7.2 recommendation: NOT APPLICABLE.** Keep magnetometer on bus 1 with the rest.

---

## 14. Analog Hub (external ADC)

**What it is** [p. 8 §6.7]: the same physical pins (2 and 3) can alternatively act as a **2-channel ADC** for reading external analog signals, with the output sampled at 240 Hz into `AH_QVAR_OUT_L/H` registers and optionally batched in FIFO.

**Trade-off:** mutually exclusive with Qvar and with Sensor Hub (all share pins 2/3).

**Use cases:** reading an external thermistor, pressure transducer, biosignal electrode — anything that produces a low-frequency analog voltage.

**v7.2 applicability: NONE.**
- The wearable's analog sensing (skin temp, light) uses dedicated digital sensors (TMP117 [20.09], VEML6030 [20.06]). No need for the LSM's ADC.

**v7.2 recommendation: NOT APPLICABLE.** Could be useful in v3+ for some custom biosignal (skin conductance / GSR), but not now.

## Warnings & Errata (advanced features specific)

| ID | Title | Source | Severity | Description / Mitigation |
|---|---|---|---|---|
| WARN-01 | **Bank switching is the #1 advanced-feature footgun** | [p. 56 §9.1] | **HIGH** | After enabling `EMB_FUNC_REG_ACCESS = 1`, all subsequent reg writes go to the embedded bank — including accidental writes to "0x10" which is **not** CTRL1 anymore. Must always switch back. **Mitigation:** wrap embedded access in `bank_switch(EMBED) … bank_switch(MAIN)` helpers in FW. Add a debug assert that reads back `FUNC_CFG_ACCESS` after every embedded function call and warns if not 0. |
| WARN-02 | **Pedometer runs at 30 Hz regardless of accel ODR — but accel must be ≥ 30 Hz** | [p. 4 §2.1] | MED | Pedometer is "always on" once enabled, but it needs the accel to provide data at ≥ 30 Hz. If FW drops accel below 30 Hz (e.g., LP mode 1 at 15 Hz), step counting stops. **Mitigation:** keep accel ODR ≥ 30 Hz when pedometer enabled. Activity/Inactivity sleep mode default is fine (it doesn't drop below 30 Hz unless XL_INACT_ODR is set lower). |
| WARN-03 | **MLC + FSM share 16 KB total memory** | [p. 7 §2.6 (implicit) + AN5804] | MED | A complex MLC classifier with deep trees can starve FSM memory. **Mitigation:** budget at design time. ST tools warn at compile-time. Don't expect to fit "everything." |
| WARN-04 | **Qvar disables SPI 3/4-wire mode on pins 2/3** | [p. 11 Table 2 footnote 1; p. 70 CTRL7] | MED | If CS is grounded (SPI mode) AND Qvar is enabled, behavior is undefined. v7.2 uses I²C (CS=high) so this is moot — but if ever moving to SPI, the conflict is real. |
| WARN-05 | **ASC (FSM writing to CTRL regs) locks out host writes** | [p. 74 §9.24 CTRL_STATUS] | MED | When FSM owns the CTRL regs (FSM_WR_CTRL_STATUS = 1), host writes are silently ignored — only reads work. **Mitigation:** check the status bit before writing CTRL1/2/3/etc. when ASC is active. Or briefly disable ASC during host config bursts. |
| WARN-06 | **SFLP quaternion W must be reconstructed by host** | [p. 8 §2.8] | LOW | Only X, Y, Z are batched in FIFO; the host computes `W = sqrt(1 - X² - Y² - Z²)`. The sign of W is **assumed positive** by convention. **Mitigation:** ensure FW does the reconstruction. If a custom orientation algorithm needs W's sign, can't get it from SFLP alone. |
| WARN-07 | **Activity/inactivity threshold weight defaults to 7.8125 mg/LSB → low full-scale** | [p. 93 §9.55] | LOW | With default weight (000) and max threshold (6-bit = 63), max wake threshold is 63 × 7.8125 = 492 mg. For "violent wake event needed," that may be too low. **Mitigation:** select higher weight (e.g., 62.5 mg/LSB → max 4 g threshold) for higher thresholds. |
| WARN-08 | **Embedded function event clear semantics differ per source** | [p. 76–94 various] | LOW | WAKE_UP_SRC clears on read; FSM/MLC results clear differently (require explicit ack). **Mitigation:** consult each source register's description; don't assume "read = clear" universally. |
| WARN-09 | **MLC requires training data + compute pipeline OFF the device** | [AN5804] | INFO | Cannot train MLC on the device itself — requires Python (scikit-learn, pandas) workflow. **Mitigation:** budget engineering time for data collection + training infra if MLC is planned. |
